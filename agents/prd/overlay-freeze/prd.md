# PRD: overlay-freeze

## Goal

hide 데스크톱 앱에서 브라우저 페이지를 띄워 두고 일하는 운영자는, 팔레트, 메뉴, 팝오버, 대화상자, 좁은 창의 Tools 오버레이, 툴팁 같은 셸 레이어가 페이지와 겹칠 때 페이지가 그 레이어 위에 그려지는 프레임을 보지 않습니다.
지금은 네이티브 `WebContentsView`가 셸 HTML보다 항상 위에 그려지고, 오버레이가 열린 뒤 비동기 캡처가 끝날 때까지 페이지가 숨지 않으며, Tools 오버레이는 오버레이로 인식되지 않고, 툴팁은 페이지 가장자리에서 잘립니다(이슈 #323).
목표 문장: 셸의 모든 레이어가 페이지 위에 보이고, 페이지가 레이어 위에 있는 프레임이 없습니다.

## Non-goals

- 툴팁이 열릴 때 페이지를 freeze하지 않습니다. 툴팁은 너무 자주 열리고 닫힙니다. 어느 쪽에 놓아도 페이지와 겹치는 툴팁은 지금처럼 페이지 아래에 그려집니다. 그런 배치가 실제로 보고되면 다시 봅니다.
- 오버레이용 네이티브 뷰를 하나 더 두지 않습니다. 포커스와 키보드 처리가 렌더러 둘로 갈라집니다.
- 사이드 패널 구조(#321의 세 컬럼)는 바꾸지 않습니다. #321이 Tools 오버레이를 없애면 B6의 근거가 사라지고, 그때 그 선택자 항목도 함께 지웁니다.
- 페이지 내용이 바뀔 때마다 스틸을 다시 찍지 않습니다. 주기 캡처는 없습니다(D-03).
- `.pen` 디자인 파일은 바꾸지 않습니다. 새 컴포넌트나 토큰이 없습니다.

## Decisions

| D-n | 결정 | 근거 |
| --- | --- | --- |
| D-01 | 모달 성격의 오버레이(팔레트, 메뉴, 팝오버, 대화상자, Recent Panels와 Recent Projects 목록, 셸 드래그, Tools 오버레이)는 freeze를 유지하되, 오버레이가 페이지와 처음 겹치는 그 sync에서 페이지를 바로 숨깁니다. 캡처를 기다리지 않습니다. | 운영자: "ㅇㅇ 너의 추천대로 해줘" (HANDOFF 결정 1) |
| D-02 | 숨긴 페이지 자리에는 페이지가 idle일 때 미리 찍어 둔 스틸(캐시)을 바로 그립니다. 캐시가 없으면 먼저 숨기고 빈 자리를 보이다가 스틸이 도착하면 그립니다. 잠깐 비는 것이 페이지가 오버레이 위에 있는 것보다 낫습니다. | 운영자: "ㅇㅇ 너의 추천대로 해줘" (HANDOFF 결정 1) |
| D-03 | 캐시는 앞에 있는 Workspace에서 보이는 페이지마다 스틸 하나입니다. 페이지의 로드가 끝났을 때, 주소가 바뀌었을 때, 슬롯 크기가 바뀌었을 때, 화면에 다시 나타났을 때만 조용한 시간(약 0.5초)이 지난 뒤 한 번 찍습니다. 가려졌거나, 숨었거나, 로드 중이거나, 실패한 페이지는 찍지 않고, 페이지당 동시에 하나만 찍습니다. 디스플레이가 닫히거나 앞 Workspace가 바뀌면 버립니다. 크기나 주소가 다른 스틸은 쓰지 않습니다. | 가정: HANDOFF "state its cost, its refresh trigger and its bound (no per-tick capture, cap the cache)"를 만족하는 가장 단순한 트리거 집합 |
| D-04 | 오버레이가 덮는 순간에도 새 캡처를 숨기기 직전에 요청하고, 도착하면 캐시 스틸을 그것으로 바꿉니다. 그래서 캐시가 오래됐어도(스크롤 뒤 등) 몇 프레임 안에 현재 내용으로 바뀝니다. | 가정: D-02의 "스틸이 도착하면 그린다"를 캐시가 있을 때도 적용해 오래된 스틸이 남지 않게 함 |
| D-05 | 툴팁은 freeze 대상에서 빼고, 보이는 페이지의 사각형을 피하는 쪽에 놓습니다. 원래 쪽, 반대쪽, 그다음 수직인 두 쪽 순서로 창 안에 들어가면서 페이지와 겹치지 않는 첫 쪽을 고르고, 없으면 원래 쪽을 씁니다. | 운영자: "ㅇㅇ 너의 추천대로 해줘" (HANDOFF 결정 2, "Radix collision boundary or flip") |
| D-06 | 좁은 창에서 View 영역 위에 뜨는 Tools 오버레이를 오버레이 대상에 넣습니다. 구현 전에 지금 정말 덮이지 않는지 e2e로 먼저 확인하고, 이미 덮인다면 이 항목은 빼고 그렇게 보고합니다. | 이슈 #323 "확인하지 못했습니다", HANDOFF "confirm whether it is really not covered today" |
| D-07 | 오버레이용 두 번째 네이티브 뷰는 기각합니다. | 운영자: "ㅇㅇ 너의 추천대로 해줘" (HANDOFF 결정 3) |
| D-08 | 브라우저 페이지가 없는 화면(일반 브라우저 탭, 페이지가 없는 Workspace)에서는 툴팁 배치와 오버레이 동작이 지금과 같습니다. | 가정: 변경 범위를 네이티브 페이지가 있을 때로 한정 |
| D-09 | 전달: `main` 대상 PR을 열고 CI를 지켜보며 병합하지 않습니다. PR 제목과 본문은 한국어로 씁니다. | 운영자: "PR 올리는것까지 해볼까?", HANDOFF "Never merge a pull request" |
| D-10 | 원칙 입력: 선언된 `~/projects/oh-my-principle`에 이 기기에서는 `ROOT.md`가 없어 `sasu principles list`가 실패했습니다. 대신 `engineering.md`와 HANDOFF에 적힌 디자인 원칙(기존 패턴 따르기, 상태는 문장이 아니라 모양으로, 모든 상태 설계, 운영자가 손쓸 수 없는 실패는 진단 로그로)을 읽고 따릅니다. 캡처 실패는 화면이 아니라 진단 로그로 갑니다. | 가정: 원칙 저장소 읽기 실패를 보고하고 HANDOFF의 원칙 목록으로 대체 |

## Technical structure

새 서비스, 스키마, 와이어, 저장소 경계는 없습니다. core, hided, Herdr 계약은 바뀌지 않습니다.
웹 셸의 브라우저 sync 루프가 페이지 숨김을 오버레이 감지와 같은 sync로 당기고, 앞 Workspace의 보이는 페이지마다 스틸 하나를 캐시합니다. 데스크톱 호스트의 캡처 IPC는 그대로 쓰고, 덮는 순간의 새 캡처는 숨김 sync보다 먼저 보냅니다.
툴팁 배치는 셸의 공용 툴팁 컴포넌트가 sync 루프가 마지막으로 보낸 보이는 페이지 사각형을 읽어서 고릅니다.
Tools 오버레이는 오버레이 선택자에 들어가고, 열리고 닫힐 때 sync 루프에 알립니다.
`docs/BROWSER_DISPLAYS.md`(Overlays)와 `docs/UI_BEHAVIOR.md`(Browser displays, 툴팁)를 같은 변경에서 고칩니다.

## Risks

- 캐시 스틸이 페이지의 현재 내용보다 오래될 수 있습니다(스크롤, 입력, 실시간 페이지). 덮는 순간의 새 캡처(D-04)가 몇 프레임 안에 바꿉니다.
- 캡처는 메인 프로세스에서 PNG로 인코딩되므로 트리거마다 짧은 작업이 생깁니다. 트리거 네 가지, 조용한 시간, 페이지당 하나 in-flight, 보이는 페이지 수로 제한됩니다.
- 덮는 순간의 새 캡처는 같은 렌더러에서 보낸 IPC가 순서대로 처리된다는 데 기댑니다. 숨긴 뒤 캡처가 비면 캐시 스틸이나 빈 자리가 남고, 페이지가 위에 보이지는 않습니다.
- 툴팁 쪽 선택은 렌더된 툴팁 크기를 재서 Radix가 위치를 잡기 전에 정합니다. Radix가 창 경계 때문에 다시 뒤집으면 원래처럼 페이지 아래에 그려질 수 있습니다.
- 이 기기(mac mini)는 화면이 잠겨 있습니다. 시각 확인은 e2e가 창 id로 찍는 캡처에 한정하고, 직접 눈으로 본 확인은 하지 않았다고 표시합니다. 프레임 단위의 "한 프레임도 없음"은 단위 테스트(숨김과 오버레이 감지가 같은 sync)와 e2e로 근거를 대고, 고속 녹화로는 확인하지 않습니다.
- 운영자에게서 미리 받아야 할 것은 없습니다.
