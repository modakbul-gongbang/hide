# PRD: 포커스된 영역 안의 탭 순환과 포커스 표시

## Goal

hide 사용자가 Agent와 View를 오가면서 현재 키보드를 둔 영역의 이전 탭으로 예측 가능하게 돌아가고, 어느 영역이 키보드를 갖고 있는지 화면에서 바로 알 수 있게 한다.
이슈 #269의 모든 완료 조건을 구현하며, 이미 머지된 #239의 키보드 소유 경계를 확장한다.

## Non-goals

- 영역 순환을 프로젝트나 다른 영역까지 확장하지 않는다. 전체 탐색은 별도 Recent Panels로 유지하고, 범위 통합은 별도 요청에서 재검토한다.
- 새로운 창이나 탭을 자동 생성하지 않는다. 기존 탭 탐색에 대상이 없으면 현재 상태를 유지하며, 생성 UX는 기존 계약을 따른다.
- 포커스 표시 때문에 터미널·문서·브라우저 본문을 읽기 어렵게 만들지 않는다. blur는 실제 비교와 성능 검증이 승인 가능한 결과를 낼 때만 채택한다.
- 레이아웃과 선택의 권한을 웹에 옮기거나 새 패키지를 도입하지 않는다. 기존 core 권한과 입력 전달 경계를 확장한다.

## Technical structure

기존 최근 탐색 흐름에 명시적인 영역 범위를 더하고, 키보드 소유 상태를 실제 화면 표시와 네이티브 입력 전달이 함께 관찰한다.
core가 레이아웃과 확정된 선택을 계속 소유하며, shell은 미리보기와 세션 내 최근 기록만 소유한다.
네이티브 브라우저의 키 전달은 기존 desktop 호스트 경계를 확장하며 새로운 서비스·저장소·권한·Herdr topology API는 도입하지 않는다.

## Risks

- area ID가 Agent와 View에서 겹치므로 부분 식별자를 쓰면 잘못된 영역으로 이동한다. 전체 범위를 고정하고 이동·닫힘 경계를 함께 다룬다.
- native browser의 입력과 focus는 renderer 테스트만으로 증명되지 않는다. 정확히 식별된 격리 candidate 앱의 실제 페이지에서 입력·해제·취소를 관찰한다.
- 디자인 선택은 사용자 위임에 따른 가정이며 사후 취향 QA 대상으로 남긴다. 비교안을 task-local scratch에 남기고 자동 생성 design 파일은 정식 생성·이식 경로를 따른다.
- 포커스 dimming은 native page pixels에 자동 적용되지 않는다. 브라우저 화면까지 실제 가독성과 표시를 확인하고, blur는 비용을 측정해 선택한다.
- 운영 앱·서버·panes를 변경하거나 설치 번들을 교체하지 않는다. build·native QA는 worktree와 격리 Herdr에서 진행한다.
- 다른 병렬 PR과 문서가 충돌하면 최신 main 위에서 보존해 조정하고 바뀐 head에 필요한 리뷰·검증을 수행한다.
- 구현 전에 사용자가 추가로 해야 할 계정·비용·인증 작업은 없다. 완료 후 사용자는 포커스 표시의 선호와 실제 업무 흐름을 QA한다.
