# PRD: Agents 탭을 체크아웃 박스와 위임 선의 그래프 한 뷰로

## Goal

Overview의 Agents 탭을 보는 운영자는 지금 체크아웃 lane 모드와 계보 모드를 오가며, 선이 카드를 뚫고 지나가는 그림에서 누가 누구에게 일을 맡겼는지 읽어내야 한다.
이 변경은 Agents 탭을 체크아웃 박스와 위임 선으로 된 그래프 한 뷰로 바꿔, 어디서 누가 일하고 누가 나를 기다리는지를 한 화면에서 읽고 그 자리에서 바로 행동하게 한다.
위임으로 일하는 에이전트가 늘면서 지금 화면이 읽히지 않게 되었고, 2026-10-01 HTML 프로토타입 v3(https://claude.ai/artifact/8cWK5TurUXXtS2Jem3iBxf)로 모양을 정했다.

## Non-goals

- 체크아웃/계보 모드 토글과 두 모드를 남기지 않는다(D-02). 계보 모드로 보던 사슬은 그래프의 선과 행 올려두기로 본다. 재검토: 그래프로 답할 수 없는 계보 질문이 생길 때.
- 에이전트 사이 상호작용(hcoord request·watch, 순서 넘기기)은 그리지 않는다(D-13). 막힌 request는 지금처럼 hcoord로 확인한다. 재검토: 막힌 request 오버레이를 다룰 다음 그래프 PRD.
- 같은 pane에서 에이전트가 바뀌면 옛 부모 관계를 물려받는 문제는 이 PRD에서 고치지 않는다(D-12). 별도 변경이 먼저 머지되고 이 PRD는 그것을 전제로 한다. 재검토: 그 변경 없이 구현을 시작하려 할 때.
- 폰 동반 앱(/m/)의 에이전트 화면은 바꾸지 않는다(D-21). 재검토: 폰에서 위임 관계를 보고 싶다는 요청.
- 정렬 컨트롤과 provider 필터는 두지 않는다(D-09, D-10). 순서는 주의 순서로 고정이다. 재검토: 운영자가 다른 순서를 요청할 때.
- 앱 안 움직임 끄기 토글은 두지 않는다(D-20). OS의 동작 줄이기 설정만 따른다.
- Herdr events_lost 처리는 이 PRD가 아니라 Herdr pin을 0.9.2 이상으로 올리는 변경이 맡는다(D-25).
- core, hided, Herdr 계약, 스냅샷 필드는 바꾸지 않고 새 웹 의존성을 들이지 않는다(D-16, D-31). 지운 두 모드의 코드와 테스트를 옆에 남기지 않는다(engineering principles 1, D-02).

## Decisions

| D-01 | Agents 탭은 체크아웃 박스 그래프다: 체크아웃은 박스, 에이전트는 박스 안의 행, 다른 체크아웃으로 맡긴 위임은 박스 사이 선, 같은 체크아웃 안 위임은 박스 안 들여쓰기. | 사용자: AskUserQuestion에서 'A. 체크아웃 박스 그래프' 선택 |
| D-02 | 체크아웃/계보 토글을 없애고 이 그래프 한 뷰로 대체하며, lane과 계보 코드는 같은 변경에서 지운다. | 사용자: '아닌가 하나만 있어도 되나!!', 프로토타입 뒤 '우선 UI 자체는 그렇게 하는거 넘 좋고' |

| D-07 | 에이전트가 모두 쉬는 박스는 기본으로 '쉬는 체크아웃 N' 한 줄로 접히고, 그쪽 선은 맡긴 행의 하위 배지로 바뀐다. 한 프로젝트 Overview에서 primary 박스는 늘 보인다. | 사용자: 'agent가 따로 안떠있으면 안보여야하는거아냐? default가 그래야하는 것 같기도' |

## Behaviors

| # | 사용자가 관찰하는 행동 | 결정 |
| --- | --- | --- |
| B1 | 프로젝트 행, Overview 행, 팔레트, ⌘⇧H로 Overview를 열면 Agents 탭이 그래프 한 뷰로 열리고, 앞에 있는 체크아웃의 박스(그 체크아웃에 박스가 없으면 main 박스)가 선택 테두리를 달고 보이는 곳으로 스크롤된다. 체크아웃/계보 모드 컨트롤은 어디에도 없다. | D-02, D-22 |
| B2 | 에이전트가 있는 체크아웃마다 박스가 하나 서고, 그 체크아웃 pane에서 일하는 에이전트가 박스 안에 한 줄씩 선다. | D-01 |
| B3 | 위임이 들어오지 않은 박스는 첫 열에, 위임이 들어온 박스는 가장 깊은 부모 박스의 다음 열에 선다. 워크트리에서 부모 없이 바로 시작한 에이전트의 박스도 첫 열이다. | D-03 |

## Technical structure

- 바뀌는 곳은 웹 셸의 Overview Agents 탭뿐이다. lane 배치와 계보 배치, 두 렌더러, 모드 상태와 모드 컨트롤을 지우고, 스냅샷에서 이미 받는 에이전트 행(부모·자식 pane id, 체크아웃, 탭의 pane 목록, PR·이슈·워크트리 사실)으로부터 그래프 모델(박스, 행, 받침, 선, 접기, 배지)을 계산하는 순수 함수와 그 렌더러로 바꾼다(D-16, D-31).
- 좌표는 측정 없이 행 수로 결정된다. 선은 SVG로 박스 뒤에 그리고, 위치 이동은 상태가 바뀐 화면에서만 보간하며, 흐르는 점선과 마크 회전만 CSS 애니메이션이다(D-20, D-26).
- 필터, 선택 박스, 펼친 접기 줄은 기존 Overview 화면 상태에 들어가 Recent Panels가 되살리고, 저장 설정이나 core에는 가지 않는다(D-29).
- core, hided, Herdr 계약, 스냅샷 필드, hcoord는 이 PRD에서 바뀌지 않는다. 같은 pane 재사용 문제의 세션 대조(hcoord 토큰과 core 대조)는 별도 PR로 먼저 머지된다(D-12).
- 새 크기는 design/tokens.json 제안 토큰으로, 박스는 hide-ui.lib.pen의 Component 시트로 들이고, docs/UI_BEHAVIOR.md의 Agents 두 절을 그래프 한 절로 바꾼다(D-34).
- 전달은 main으로 가는 PR 하나다(D-32).

## Risks

- 세션 대조 변경(D-12)이 먼저 머지되지 않으면 같은 pane에 새로 뜬 에이전트가 옛 부모 밑에 그려진다. 구현 시작 전에 그 변경이 main에 있는지 확인한다.
- 위임이 열 둘 이상을 건너는 선(가장 깊은 부모 기준 열 규칙에서 얕은 부모가 낸 선)은 사이 열의 박스를 피해야 해서 라우팅이 가장 어렵다. 역방향 점선은 박스를 지날 수 있으며 이는 순환에만 허용된다.
- 흐르는 점선은 상시 애니메이션이라 idle CPU를 쓴다. D-26 합격선으로 막고, 측정은 네이티브 데스크톱 앱에서 한다(헤드리스 60Hz 프레임 측정은 빈 페이지에서도 떨어진 적이 있다).
- 기존 lane·계보 e2e와 단위 테스트가 대량으로 바뀐다. 지운 모드의 테스트는 같은 변경에서 지운다.
- 데스크톱 확인은 격리된 Herdr 서버와 정확히 식별한 후보 앱에서만 하고, 운영자의 앱·pane·서버는 건드리지 않는다.
- Herdr pin을 0.9.2 이상으로 올리면 events_lost 처리가 필요하며 그 변경이 맡는다(D-25).
- 구현 전에 운영자가 할 일은 없다. 세션 대조 변경의 머지만 선행 조건이다.
