# PRD: ⌘K를 이동 팔레트로

## Goal

운영자는 사이드바, ⌥1-9, ⌃Tab이 더 빨라서 ⌘K를 거의 누르지 않는다.
이 변경으로 ⌘K는 두 가지 일만 하는 곳이 된다: 이름이나 #번호로 어느 기기·프로젝트의 에이전트, 프로젝트, checkout, 기기, PR, 이슈든 찾아가는 일, 그리고 지금 보고 있는 것과 연결된 이슈, PR, checkout, 부모·하위 에이전트로 ↵ 한 번에 가는 일.
명령 실행은 단축키와 메뉴가 맡고, ⌘K에는 `에이전트 시작…` 하나만 남는다.

## Non-goals

- 모든 프로젝트의 PR·이슈를 미리 읽어 두는 색인은 만들지 않는다. 결과: 앱 실행 중 한 번도 읽지 않은 프로젝트의 PR·이슈는 `GitHub에서 검색` 행으로만 찾는다. 다시 볼 조건: 운영자가 그 행을 자주 써야 할 만큼 불편하다고 말할 때(2단계 색인).
- 원격 기기 프로젝트의 PR·이슈와 그 관계는 다루지 않는다. 결과: mini의 에이전트·checkout은 이름으로 찾지만 PR·이슈 관계는 보이지 않는다. 다시 볼 조건: 원격 checkout과 PR을 이어 볼 필요가 생길 때.
- 자연어 해석과 같은 일의 이슈·PR·에이전트를 한 행으로 묶는 태스크 행은 만들지 않는다. 다시 볼 조건: 써 보니 같은 일의 결과가 중복돼 거슬릴 때.
- PR·이슈 본문, 라벨, 작성자 검색은 하지 않는다(목록에 그 필드가 없다).
- 최근 위치(⌃Tab), 내 차례 확인(레일 배지와 Agents), 관계 자세히 보기(오른쪽 패널 Overview)는 ⌘K에 넣지 않는다.
- GitHub 읽기의 15초 제한 시간과 PR 목록 읽기 비용(아래 Risks)은 이 변경에서 고치지 않는다.

## Decisions

## Technical structure

- 웹: ⌘K 결과 모델이 명령 대신 PR·이슈 종류와 관계(이슈, checkout 그룹, PR, 계보)를 갖는다. 관계는 스냅샷에 이미 있는 `checkout.task_key`·`closes_task_keys`, `checkout.pull_request`, `workspace.tasks`, 에이전트 계보 필드에서 웹이 계산한다. ⌘K 전용 넓은 배치를 쓰고 ⌘P·시작 패널이 쓰는 셸과 폭 토큰은 바꾸지 않는다. 명령 항목을 만들던 코드는 마지막 사용처와 함께 지운다.
- 앞 프로젝트 한 번 읽기는 Home Overview가 쓰는 기존 `github_request {refresh:false}`를 그 프로젝트 하나에 보낸다. GitHub 읽기 주기와 캐시는 바꾸지 않는다.
- core: 사용자가 고를 때만 도는 GitHub 검색 읽기를 하나 더한다. 기존 `gh` 허용 목록과 15초 제한, 런타임 잠금 밖 worker 규칙을 따르고, 한 번에 하나만 돌며, 결과 수에 상한이 있고, 결과는 요청 id로 스냅샷에 답한다. 대상 저장소는 이 Mac에 등록된 GitHub 프로젝트다.
- 단축키 레지스트리에 영역 포커스·크기 명령을 더하고 데스크톱 메뉴가 그것을 싣는다. ⌘P에 옆에 열기 키를 더한다.
- 데이터 쓰기, 마이그레이션, 인증, 원격 기기 helper 변경은 없다.

## Risks

- `gh pr list`(PR 200개와 CI 롤업)가 2026-10-01 실측 11.8초·13.2초로 core의 15초 제한에 가깝다. 네트워크가 느리면 B8의 첫 읽기가 시간 초과로 실패해 B9 상태가 될 수 있다. 제한 시간과 읽기 비용은 별도 이슈로 다룬다.
- ⌘K 명령을 쓰던 web·desktop e2e(s6, s7, agent-tab-groups, home, start-panel, browser, device-home)는 새 경로로 다시 써야 하고, 그 과정에서 명령이 정말로 다른 경로로 닿는지 확인된다.
- `quick/device-rail-badges`와 같은 파일(`actions.ts`, `shortcuts.ts`, 사이드바 머리, gallery, s2·s7 e2e)을 건드려 리베이스 충돌이 난다(D-19). 리베이스 뒤에는 실행 기준점이 바뀌어 `/ship`이 거부할 수 있고, 그때는 저장소 템플릿으로 PR을 직접 연다.
- GitHub 검색 API는 분당 호출 수 제한이 있다. 사용자가 고를 때만 부르고 같은 검색어 중복 실행을 막아(B19) 한도에 닿지 않게 한다.
- 가정으로 둔 D-08~D-11, D-15~D-17은 운영자가 PRD를 읽고 뒤집을 수 있다. 구현 전에 운영자에게서 따로 필요한 일은 없다.
