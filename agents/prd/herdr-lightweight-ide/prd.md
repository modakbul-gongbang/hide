# PRD: herdr-ide: herdr 기반 macOS 네이티브 IDE

## 1. Summary

herdr(오픈소스 터미널 워크스페이스 매니저)를 1등 시민으로 두는 macOS 네이티브 데스크톱 IDE `herdr-ide`를 새로 만든다.
앱은 단일 창에 좌측 native 사이드바(spaces/agents), 중앙 터미널, 우측 파일 워크벤치를 배치한다.
중앙 터미널에는 libghostty 서피스 위에서 herdr TUI 클라이언트를 통째로 실행해 기존 herdr 조작 경험과 단축키를 그대로 보존하고, TUI 자체 사이드바만 숨긴다.
사용자가 특정 pane을 선택한 상태에서 ⌘E를 누르면 그 pane의 작업 디렉터리를 루트로 하는 파일트리와 뷰어가 우측에 열리고, 터미널은 사라지지 않고 폭만 줄어든다.

해결하려는 불편은 구체적이다.
에이전트가 생성한 이미지나 산출물을 TUI 안에서 확인하기 어렵고, 그때마다 VS Code를 새로 여는 것이 번거롭다.

이 PRD는 v1 전체를 다룬다.
v1의 완료 판정은 골든 시나리오 실사용 통과다.

### Approval checklist

승인 전에 다음을 확인해 주세요.

- **스코프와 비목표 경계** — 워크벤치는 뷰어 + 가벼운 편집 + 검색까지이며 LSP, git 커밋 UI, 외부 뷰어 플러그인 배포 계약, 크로스플랫폼, 리모트 편집·검색은 명시적 비목표다. (3장)
- **기술 구조** — macOS 네이티브 Swift 앱 + libghostty 터미널 서피스 + WKWebView(React) UI, herdr 연동은 소켓 API. Tauri는 근거를 갖고 기각했다. (5장)
- **인터뷰 이후 확인된 새 사실 2건** — herdr 0.8.0이 이미 사이드바 완전 숨김 옵션을 제공하고 pane cwd를 API로 노출하므로, 인터뷰에서 상정했던 herdr 포크가 기본 경로에서 빠진다. (4.2장 HD3, 5장)
- **최우선 게이팅 리스크** — libghostty 임베딩 API가 비안정이라 T1 스파이크가 나머지 전부를 선행 차단한다. 스파이크 실패 시 재논의가 필요하다. (10장 RISK1)
- **검증 모드** — 자동화 행위 테스트와 앱 런타임 확인이 완료 필수이고, mini 리모트 attach는 머신 가용성에 따라 차단 가능(blockable)이다. 골든 시나리오의 "3초" 기준은 수동 판정이다. (9장)
- **동시 편집 충돌 정책** — 외부 변경 감지 시 경고 + 재로드만 제공하고 미저장 변경 보존형 병합은 하지 않는다. 에이전트가 같은 파일을 동시에 쓰는 환경에서 편집 내용이 유실될 수 있는 정책이다. (10장 RISK4)
- **배포 모드** — 로컬 빌드 개인 사용이며 PR 자동화나 서명 배포는 하지 않는다. (10장, 12장)

## 2. Problem, Goal, And Users

### 사용자

herdr로 여러 코딩 에이전트를 동시에 굴리는 단일 개발자(호연).
현재 Ghostty 위에서 herdr TUI를 쓰고 있으며 `~/.config/herdr/config.toml`에 커스텀 키바인딩과 `herdr-file-viewer`, `official.browser` 등 플러그인을 이미 운용 중이다.

### 문제

에이전트가 만들어낸 산출물, 특히 이미지 파일을 확인하려면 TUI 환경을 벗어나야 한다.
`herdr-file-viewer` 플러그인이 파일트리를 제공하지만 read-only이고 이미지 렌더링이 없다.
VS Code를 경로 지정해 새로 여는 우회는 매번 창을 전환해야 해서 흐름이 끊긴다.

### 목표

터미널을 떠나지 않고, 지금 보고 있는 에이전트 pane의 작업 경로를 한 번의 키 입력으로 시각적으로 탐색·확인·수정할 수 있게 한다.
동시에 기존 herdr 조작 경험(단축키, 플러그인, 워크스페이스 개념)을 하나도 잃지 않는다.

### 성공의 모습

하루 작업을 터미널 앱 대신 herdr-ide로 시작해도 아쉬움이 없고, 이미지 확인을 위해 다른 앱을 여는 일이 사라진다.

## 3. Scope And Non-Goals

### In Scope (v1)

- macOS 단일 창 앱: 좌 native 사이드바 / 중앙 터미널 / 우 워크벤치 3분할 레이아웃.
- 중앙 터미널에서 herdr TUI 클라이언트 전체 실행, TUI 사이드바는 숨김.
- native 사이드바: spaces 목록과 전환, agents 목록과 상태·attention 표시 및 포커스 이동, 로컬/리모트 서버 스위처, 새 워크스페이스 생성.
- ⌘E 워크벤치 토글: 선택 pane의 작업 디렉터리를 루트로 파일트리 열기, 터미널 유지·축소, 같은 키로 복귀.
- 뷰어: 이미지, 마크다운 렌더링, 코드 구문 강조, git diff. 파일 타입에서 뷰어로 가는 내부 확장 구조 위에 구현.
- 가벼운 편집: 텍스트 파일 인라인 수정과 저장, 외부 변경 감지 시 경고와 재로드.
- 검색: 파일명 필터와 텍스트 검색, `.gitignore` 존중, 숨김 파일 기본 제외(토글 가능).
- 리모트: herdr 리모트 서버 attach와 리모트 pane의 파일 보기 전용 탐색.
- herdr 서버 비독점: 앱 실행 중에도 별도 터미널에서 herdr 클라이언트 사용 가능.
- 설정: 워크벤치 토글 단축키 변경, 숨김 파일 표시 토글.

### Non-Goals (v1)

- **LSP, 자동완성, 정의 이동, 리팩터링** — 편집은 단순 수정 수준으로 한정한다. 무거운 편집이 필요하면 사용자가 별도 에디터를 연다. 실사용에서 편집 깊이 부족이 반복 확인되면 재논의한다.
- **git 커밋·스테이징 UI** — diff는 읽기 전용으로 보여주기만 한다. git 조작은 터미널에서 한다.
- **외부 뷰어 플러그인 배포 계약** — 매니페스트, 샌드박싱, 설치 흐름은 만들지 않는다. 새 뷰어는 herdr-ide 코드에 직접 추가한다. 사용자가 직접 개발하는 앱이므로 v1에서 외부 계약의 이득이 비용보다 작다.
- **리모트 파일 편집과 리모트 검색** — 리모트는 보기 전용이다. 저장 충돌, 권한, 원격 검색 실행의 엣지 케이스 비용이 크다. 리모트에서 수정이 필요하면 해당 리모트 pane의 터미널에서 한다.
- **워크벤치 재오픈 시 상태 복원** — 마지막 열람 파일과 스크롤 위치를 복원하지 않고 트리 루트만 다시 계산한다. 실사용에서 불편이 확인되면 재논의한다.
- **미저장 변경 보존형 diff·병합** — 외부 변경 충돌 시 경고와 재로드만 제공한다.
- **macOS 외 플랫폼** — libghostty의 검증된 임베딩 경로가 macOS Swift뿐이다.
- **서명·공증·자동 배포** — 로컬 빌드로 개인 사용한다.
- **워크벤치 포커스 자동 추적** — 워크벤치는 ⌘E를 누른 시점의 pane에 고정되며 이후 pane 포커스 변경을 따라가지 않는다.

## 4. Pre-Work And Required Decisions

### 4.1 Pre-Work Before Implementation

- **PW1. 전체 Xcode 설치와 라이선스 동의.** 현재 이 머신에는 Command Line Tools만 있고(`xcode-select -p` → `/Library/Developer/CommandLineTools`) `xcodebuild`가 없다. AppKit·WKWebView 기반 macOS 앱 번들 빌드에는 전체 Xcode가 필요하다. Xcode 설치는 App Store 로그인과 Apple ID 소유자 확인이 필요해 에이전트가 대신 수행할 수 없다. 설치 후 `sudo xcode-select -s`와 라이선스 동의(`sudo xcodebuild -license accept`)도 관리자 권한이 필요하다.

그 외 도구(Zig, ripgrep, Ghostty 소스 체크아웃, 프로젝트 스캐폴딩, 테스트 하니스)는 에이전트가 직접 준비하므로 pre-work가 아니라 구현 태스크다.

### 4.2 Human Decisions Before PRD Approval

- **HD1. 스코프와 비목표 승인.** 특히 LSP·git UI·외부 플러그인 계약·리모트 편집을 v1에서 제외하는 경계를 승인한다.
- **HD2. 기술 구조 승인.** macOS 전용 Swift 앱 + libghostty + WKWebView 조합과, herdr TUI를 pane 단위로 재구현하지 않고 통째로 실행하는 방식을 승인한다.
- **HD3. 인터뷰 이후 확인된 새 사실에 따른 방침 변경 승인.** 인터뷰에서는 herdr에 사이드바 숨김 옵션이 없으면 포크한다고 결정했으나(qa-log D-16, D-24②), 실제 herdr 0.8.0 바이너리에 `ui.sidebar_start_collapsed`와 `ui.sidebar_collapsed_mode = "hidden"`이 존재한다. 따라서 포크를 기본 경로에서 제외하고, 이 옵션의 완전 숨김 동작이 T1 스파이크에서 기대와 다를 경우에만 포크를 재논의하는 것으로 방침을 바꾼다.
- **HD4. 검증 모드 승인.** 자동화 행위 테스트와 앱 런타임 확인을 완료 필수로, mini 리모트 attach를 차단 가능(blockable)으로 두는 구성을 승인한다. 골든 시나리오의 "3초 내" 기준을 자동 계측 없이 수동 판정하는 것도 함께 승인한다.
- **HD5. 동시 편집 충돌 정책 승인.** 경고와 재로드만 제공하고 미저장 변경을 보존하는 병합을 하지 않는 정책은 에이전트 동시 편집 환경에서 편집 유실 가능성을 남긴다. 이 트레이드오프를 승인한다.
- **HD6. 배포 모드 승인.** 로컬 빌드 개인 사용이며 PR 자동화, CI, 서명 배포를 하지 않는다.

## 5. Major Technical Structure Changes

이 저장소는 커밋이 없는 빈 그린필드이므로 전부 신규 구조다.

- **신규 macOS 앱 번들.** Swift + AppKit 기반 단일 창 앱. 창은 세 영역(native 사이드바 / 터미널 / 워크벤치)으로 분할된다.
- **libghostty 임베딩 경계.** Ghostty를 고정 버전으로 소스 빌드해 libghostty를 얻고, 그 터미널 서피스를 앱 창의 네이티브 뷰로 호스팅한다. 이 경계가 프로젝트 최대 기술 리스크이며 T1이 이를 선행 검증한다. 대안이었던 Tauri는 libghostty 임베딩 선례가 전무하고 Tauri 계열 터미널이 모두 xterm.js로 회귀한다는 리서치 근거로 기각했다.
- **herdr 소켓 API 클라이언트 경계.** 앱은 herdr 서버의 또 다른 클라이언트가 된다. Unix 소켓으로 요청·응답과 이벤트 구독을 처리하며, herdr 본체를 수정하지 않는다. 이 경계가 native 사이드바 데이터와 pane cwd 조회를 담당한다.
- **WKWebView UI 레이어.** 사이드바와 워크벤치 UI는 웹 기술(React)로 구현하고 WKWebView로 호스팅한다. Swift 측과는 메시지 브리지로 통신한다. 뷰어 확장 구조가 이 레이어 안에 있다.
- **파일 접근 계층.** 로컬은 파일시스템 직접 접근, 리모트는 herdr가 이미 사용하는 SSH 경로를 통한 읽기 전용 접근. 앱은 자체 자격증명을 저장하지 않는다.
- **외부 프로세스 의존.** 중앙 터미널이 herdr 클라이언트 프로세스를 띄운다. 앱은 herdr 서버를 소유하거나 독점하지 않으며, 서버 수명주기는 herdr가 계속 관리한다.

herdr 본체 포크는 기본 경로에서 제외한다(HD3). 스파이크에서 사이드바 완전 숨김이 확인되지 않을 때만 컨틴전시로 재논의한다.

## 6. Requirements

- R1. 앱은 macOS에서 단일 창으로 실행되며 좌측 native 사이드바, 중앙 터미널, 우측 워크벤치 영역을 가진다.
- R2. 중앙 터미널은 libghostty 서피스 위에서 herdr TUI 클라이언트를 실행하며, herdr의 기존 키 조작과 설치된 herdr 플러그인이 그 안에서 그대로 동작하고, TUI 자체 사이드바는 보이지 않는다.
- R3. native 사이드바는 herdr 서버로부터 spaces와 agents 상태를 받아 표시하고, 항목 선택으로 해당 워크스페이스·pane 포커스 전환과 새 워크스페이스 생성을 수행하며, 상태 변화가 폴링 지연 없이 반영된다.
- R4. 앱은 로컬 herdr 서버와 리모트 herdr 서버에 각각 연결할 수 있고 사이드바에서 대상 서버를 전환할 수 있으며, 리모트 연결은 herdr가 이미 사용하는 SSH 설정을 재사용하고 앱은 자격증명을 저장하지 않는다.
- R5. 사용자가 pane을 선택한 상태에서 워크벤치 토글 단축키를 누르면 그 pane의 작업 디렉터리를 루트로 하는 파일트리가 우측에 나타나고 터미널은 닫히지 않은 채 폭만 줄며, 같은 키로 원래 폭으로 복귀한다.
- R6. 워크벤치는 이미지, 마크다운, 코드, git diff를 각각에 맞는 방식으로 표시하며, 파일 타입에서 뷰어를 고르는 지점이 하나의 등록 구조로 통일돼 새 뷰어 종류를 추가할 때 기존 뷰어를 수정하지 않아도 된다.
- R7. 사용자는 워크벤치에서 로컬 텍스트 파일을 수정하고 저장할 수 있으며, 저장 대상 파일이 열람 후 외부에서 변경된 경우 그 사실을 저장 전에 인지할 수 있다.
- R8. 사용자는 워크벤치에서 파일명과 파일 내용을 검색할 수 있고, 검색은 `.gitignore` 규칙과 숨김 파일 제외 설정을 따르며, 사용자가 별도로 설치하지 않은 외부 검색 바이너리에 의존하지 않는다.
- R9. 리모트 서버의 pane에서 워크벤치를 열면 원격 경로의 파일을 탐색하고 볼 수 있으며, 편집과 검색은 사용할 수 없다는 것이 화면에서 드러난다.
- R10. 사용자는 워크벤치 토글 단축키와 숨김 파일 표시 여부를 설정에서 바꿀 수 있다.
- R11. 앱이 실행 중일 때도 별도 터미널에서 herdr 클라이언트로 같은 서버에 접속해 사용할 수 있고, 양쪽에서 발생한 상태 변화가 서로에게 반영된다.
- R12. 앱은 검증된 특정 Ghostty·herdr 버전을 대상으로 빌드·동작하며, 대상 버전이 저장소에 명시돼 있다.

## 7. Acceptance Criteria

- AC1. libghostty 서피스에서 실행된 herdr TUI가 키 입력을 받고, 창 크기 변경에 맞춰 다시 그려지고, 스크롤이 동작하고, kitty graphics 이미지가 인라인으로 표시된다. (R2)
- AC2. 앱 안의 herdr TUI에서 `prefix+f`로 기존 `herdr-file-viewer` 플러그인이 열리며, 워크벤치 토글 단축키와 서로 간섭하지 않는다. (R2)
- AC3. 사이드바가 현재 워크스페이스 목록과 에이전트별 상태(작업 중, 응답 대기 등)를 보여주고, 사이드바에서 워크스페이스나 에이전트를 선택하면 중앙 TUI가 해당 대상으로 전환되며, 터미널에서 워크스페이스를 바꾸면 사이드바 표시도 따라 바뀐다. (R3)
- AC4. 사이드바에서 새 워크스페이스를 만들 수 있고, 만들어진 워크스페이스가 터미널의 herdr TUI에도 존재한다. (R3)
- AC5. 로컬 pane을 선택하고 ⌘E를 누르면 그 pane의 작업 디렉터리가 파일트리 루트로 나타나고 터미널이 화면에서 사라지지 않으며, 다시 ⌘E를 누르면 터미널이 원래 폭으로 돌아온다. (R5)
- AC6. 워크벤치가 열린 뒤 다른 pane으로 포커스를 옮겨도 파일트리 루트는 바뀌지 않고, 그 다른 pane에서 ⌘E를 다시 누르면 새 pane의 작업 디렉터리로 바뀐다. (R5)
- AC7. pane의 작업 디렉터리를 알 수 없는 경우 워크벤치가 빈 화면으로 열리지 않고, 마지막으로 알던 경로 또는 홈 디렉터리를 루트로 열면서 경로를 찾지 못했다는 상태를 함께 보여준다. (R5)
- AC8. 이미지 파일은 이미지로, 마크다운은 렌더링된 문서로, 소스 코드는 구문이 구분되는 형태로 표시되며, 각 타입이 같은 등록 구조를 통해 뷰어와 연결된다. (R6)
- AC9. git 저장소 안의 변경된 파일에서 작업트리와 HEAD의 차이를 볼 수 있고, git 저장소가 아닌 경로에서는 diff 보기가 제공되지 않는다. (R6)
- AC10. 워크벤치에서 수정한 내용이 저장 후 디스크에 반영되고, 열람 이후 외부에서 같은 파일이 변경된 경우 사용자에게 경고와 다시 불러오기 선택지가 제시된다. (R7)
- AC11. 리모트 서버 연결에 실패하면 실패 사유와 다시 시도할 방법, 그리고 SSH 설정을 확인하라는 안내가 화면에 함께 나타난다. (R4)
- AC12. 검색 결과에 `.gitignore`로 무시되는 경로와 숨김 파일이 기본적으로 포함되지 않고, 설정에서 숨김 파일 표시를 켜면 포함되며, 결과가 없을 때 빈 상태임이 드러난다. (R8)
- AC13. 리모트 pane에서 워크벤치를 열면 원격 경로의 파일트리와 파일 내용을 볼 수 있고, 편집과 검색이 사용 불가 상태로 표시된다. (R9)
- AC14. 앱이 실행 중인 상태에서 별도 터미널로 같은 herdr 서버에 접속할 수 있고, 그 터미널에서 워크스페이스를 전환하면 앱 사이드바에도 반영된다. (R11)
- AC15. 저장소에 대상 Ghostty 버전과 herdr 버전이 기록돼 있고, 앱은 그 버전 기준으로 빌드된다. (R12)

### 9.3 Human Verification

- HV1. 골든 시나리오 실사용 판정. herdr-ide로 작업을 시작해 에이전트 생성 이미지를 해당 pane에서 ⌘E로 즉시(체감 3초 이내, 수동 판정) 확인하고, 가벼운 수정과 저장을 거쳐, mini 리모트 herdr를 사이드바에서 attach해 상태를 확인하는 흐름 전체가 실제로 쓸 만한지 사용자가 판단한다. 자동 계측 없이 수동으로 측정한다.
- HV2. 터미널 경험 보존 판정. 기존 Ghostty + herdr 사용과 비교해 렌더링 품질, 입력 지연, 폰트 표현에 실사용상 후퇴가 없는지 사용자가 판단한다.
- HV3. 워크벤치 UI의 시각적 완성도와 레이아웃 비율에 대한 최종 취향 판단.

## 10. Risks And Open Decisions

- **RISK1 (최상위, 게이팅).** libghostty 풀 임베딩 API가 비안정이며 검증된 소비자가 Ghostty 자체 macOS 앱뿐이다. T1 스파이크가 실패하면 프로젝트의 기술 전제가 무너지고 스택 재선택이 필요하다. 대응: Ghostty 버전 고정, T1을 다른 모든 태스크보다 먼저 수행, 실패 시 HV4로 사용자 재논의.
- **RISK2 (축소됨).** herdr 본체 포크 필요성. herdr 0.8.0에 사이드바 완전 숨김 옵션이 실재하므로 기본 경로에서 포크가 빠졌다. 잔여 리스크는 그 옵션의 실제 동작이 완전 숨김이 아닐 가능성이며, 그 경우에만 포크를 재논의한다.
- **RISK3.** herdr 소켓 API는 버전이 붙은 내부 프로토콜(protocol 19)이라 herdr 업그레이드 시 깨질 수 있다. 대응: herdr 버전 고정과 수동 검증 후 업데이트.
- **RISK4 (데이터 유실 가능).** 동시 편집 충돌 정책이 경고와 재로드뿐이므로, 에이전트가 같은 파일을 쓰는 도중 사용자가 저장하면 에이전트의 변경이 덮이거나 사용자의 미저장 변경이 재로드로 사라질 수 있다. 사용자가 이 단순안을 명시적으로 선택했다(HD5). 대응: 저장 전 외부 변경을 반드시 인지시키고, 실사용에서 유실이 발생하면 정책을 재논의한다.
- **RISK5.** 검색이 외부 ripgrep 바이너리에 의존하면 이 머신에서 곧바로 실패한다(설치돼 있지 않고 `rg`는 다른 도구의 별칭이다). R8이 이를 제약으로 명시했으며 구현에서 바이너리 동봉 또는 자체 구현 중 하나를 택한다.
- **RISK6.** 프로젝트 규모가 크고 macOS 네이티브·웹·시스템 프로그래밍이 섞여 있어 v1 완주까지 상당한 기간이 걸린다. 그동안 원래 불편(이미지 확인)은 해소되지 않는다. 사용자가 이 트레이드오프를 알고 자체 앱 경로를 선택했다.

**Deferred decisions**

- 워크벤치 재오픈 시 상태 복원: 실사용 불편이 확인되면 재논의(D-25).
- 편집 깊이 확장(LSP 등): 단순 수정으로 부족함이 반복 확인되면 재논의(D-10).
- 외부 뷰어 플러그인 배포 계약: 사용자 외 제3자가 뷰어를 추가할 필요가 생기면 재논의(D-27).
- 크로스플랫폼: libghostty가 GTK·기타 플랫폼 뷰 위젯을 안정 릴리스하면 재논의(D-13, D-15).

**Blocking decisions**: 없음. HD1~HD6은 승인 대상이며, 승인되면 구현을 시작할 수 있다.

## 11. Implementation Guardrails

`implement`는 다음을 사용자 승인 없이 하지 않는다.

- 승인된 스코프를 넘어서는 기능 추가. 특히 LSP, git 조작 UI, 외부 플러그인 배포 계약, 리모트 편집·검색은 비목표다.
- 5장에서 승인된 기술 구조 변경. 특히 libghostty를 xterm.js 등으로 대체하거나, herdr TUI 통째 실행을 pane 단위 재구현으로 바꾸는 것.
- herdr 본체 포크나 upstream PR 생성. HD3에서 컨틴전시로 격하됐으므로 필요해지면 먼저 보고한다.
- 앱이 herdr 서버를 독점하거나 서버 수명주기를 소유하도록 만드는 변경.
- 앱 자체 자격증명 저장소 도입이나 herdr SSH 설정 외의 인증 경로 추가.
- `~/.config/herdr/config.toml` 등 사용자의 기존 herdr 설정 파일 변경. 앱 전용 설정이 필요하면 앱 자체 설정 경로를 쓴다.
- 사용자 확인 없는 파일 덮어쓰기 동작 추가. 저장은 항상 사용자가 명시적으로 실행한 결과여야 한다.
- 승인되지 않은 외부 서비스, 텔레메트리, 네트워크 호출 추가.
- 사용자에게 보이지 않는 자동 동작(자동 저장, 자동 커밋, 백그라운드 인덱싱) 도입.

T1 스파이크가 성공 기준을 충족하지 못하면 우회 구현을 시도하지 말고 즉시 보고한다.

## 12. Implementation Result Report Contract

구현 에이전트는 다음을 보고한다.

- 상태: `Done`, `Partially Done`, `Blocked` 중 하나.
- 사용자 눈에 보이는 변화: 앱을 실행했을 때 무엇을 할 수 있게 되었는지.
- 주요 모듈·경계·데이터 흐름: 터미널 호스팅, herdr API 클라이언트, UI 브리지, 파일 접근 계층 각각의 책임 범위.
- 구현에서 실제 선택한 파일·모듈 구조와 각 책임 경계.
- 5장에서 승인된 기술 구조를 따랐는지, 벗어났다면 무엇을 왜 바꿨는지.
- T1 스파이크 결과: 성공 기준 네 항목(입력, 리사이즈, 스크롤, kitty graphics) 각각의 충족 여부.
- herdr 사이드바 숨김을 어떤 방법으로 달성했는지, 포크가 필요했는지.
- 태스크별 완료 상태와 R/AC/V 커버리지.
- 모드별 검증 증거: 빌드·정적 검사 결과, 자동화 테스트 결과, 앱 실행 확인(스크린샷 포함), 리모트 확인 또는 차단 사유.
- 추가·수정한 자동화 테스트와 각 테스트가 막는 회귀 위험.
- 고정한 Ghostty·herdr 대상 버전.
- 편집 저장 경로에서 파일 덮어쓰기가 발생할 수 있는 지점과 그 보호 장치.
- 승인 범위에서 벗어난 편차와 그 사유.
- 남은 사람 검토 항목(HV1~HV4 중 미완료분).
- 미완료 항목과 후속 후보.
- 배포는 로컬 빌드이며 PR·CI·서명 배포를 하지 않았음을 확인.
