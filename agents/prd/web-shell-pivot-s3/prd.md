# PRD: S3 Explorer + 에디터 + 뷰어

## Goal

S2(PR #132)까지 웹 셸은 탭·분할·줌·체크아웃 전환·단축키를 갖췄다.
S3는 파일 작업을 웹으로 옮긴다: 체크아웃 트리를 보고 조작하는 Explorer, CodeMirror 6 에디터와 Markdown Live·PDF·이미지 뷰어, ⌘P 빠른 열기와 ⌘K 검색, 그리고 터미널 pane에 이미지·파일을 드롭하거나 붙여 넣는 첨부.
끝나는 조건은 우산 PRD B11 그대로다: 사용자가 실제 Herdr 세션에서 Swift 앱 없이 Explorer에서 파일을 열어 값 하나를 고쳐 저장한다.

## Non-goals

- Changes/diff 탭(S4), Settings·진단·사이드바 편집 동작(S5), Swift 삭제(S6): 각자 PRD. `EditorTabKind::Diff` 탭은 S3에서 열리지 않는다.
- 대화 뷰어(`Session`/`Memory` 탭): 우산 PRD 미룸 표면. 사용자는 Swift 또는 파일로 본다. 재검토: Electron PRD.
- 등록되지 않은 경로: Explorer·⌘P·첨부 저장은 등록된 체크아웃 루트 밖을 나열하거나 쓰지 않는다(D-01). 홈 밖 프로젝트는 등록되어 있으면 보이고, 등록은 S2 입력창(`$HOME` 아래) 또는 후속 `hide open <path>` CLI.
- 새 코어 이벤트·스냅샷 형태 변경: 문서·탭·dirty·충돌·펼침 집합은 코어가 이미 소유하고(`EditorSnapshot`, `EditorDocumentSnapshot`, `ui_state.expanded_paths`), 필요한 이벤트(`file_open/file_focus/file_keep_open/file_close/file_draft/file_view/file_save/file_conflict/file_create/dir_create/path_rename/path_move/path_trash/reveal_path/editor_text_scale/terminal_attachment`)는 모두 있다. 웹이 문서 상태의 권위를 갖지 않는다.
- 저장 충돌 UX의 재설계: 현 Swift 방식(덮어쓰기 / 디스크 내용으로 다시 읽기)을 그대로 승계한다. 재검토: 사용자가 실사용 후 요청할 때 (D-03).
- 원격 기기의 파일 트리(`remote_files.rs` 표면): 미룸 목록 그대로.
- Swift 셸 변경: `macos/`는 토큰 생성기 출력 외에 바뀌지 않는다.
- 일반 웹에서 호스트 기본 앱 실행, 신뢰 가능한 네이티브 클라이언트 통합, 저장 선택창 없는 브라우저의 별도 초대형 다운로드 경로는 S3에 추가하지 않는다(D-12). 256 MiB 초과 다운로드는 저장 선택창을 지원하는 브라우저를 사용해야 하며 네이티브 통합 시 재검토한다.
- 전체 Pen 컴포넌트 리디자인은 후속으로 남기고 기존 토큰 계약(B17)은 유지한다(Q42: "리디자인은 담에 하려고! 우선 전체 기능 붙는거에 집중").

| D-11 | Markdown Live에서 문서 첫머리 YAML frontmatter(`---` 블록)는 본문과 분리해 고정 높이 영역(약 8줄)에 그 안에서만 스크롤되게 그린다. 편집은 그대로 되고, 없으면 영역도 없다. 원문 모드는 지금처럼. | 라이브 테스트 "2. 마크다운에서 frontmatter가 잇으면 위에 그냥 어느정도 공간 잡아놓고 그 안에서 스크롤되게 해두면 안되나?" |
| D-12 | 편집 상한은 코어 `MAX_EDITABLE_BYTES` 16 MiB로 올린다. 코어 변경은 이 값과 D-01/B11의 파일 경계를 실제 파일 작업까지 유지하기 위한 보강으로 한정한다. 경로 검사 후 교체로 프로젝트 밖 읽기·쓰기가 발생하지 않도록 하는 수정이며, 허용 루트·기능·UI·이벤트·스냅샷 계약은 넓히지 않는다. 초과 파일은 이유 한 줄과 다운로드 동작을 제공한다. 일반 웹은 loopback·SSH 포워딩을 같은 기기의 증거로 삼지 않고 기존 토큰 게이트 WS `file_bytes`로 내려받는다. 기본 앱 열기는 같은 기기임을 신뢰할 수 있는 네이티브 환경에서만 허용하며 그 통합은 후속이다. S3는 파일 저장 선택창이 있는 브라우저를 전제로 하며, 미지원 브라우저에 별도 초대형 다운로드 경로를 추가하지 않는다. 기존 256 MiB 이하의 제한된 Blob 대체 경로는 유지할 수 있지만 그보다 큰 파일을 메모리에 모으거나 새 HTTP 바이트 엔드포인트를 추가하지 않는다. 기존 로컬 브라우저 기본 앱 열기는 이 결정으로 대체한다. | Q39의 16 MiB 결정 유지. 2026-09-24 사용자: "다운로드 기본 정책으로 변경 승인 (추천)", "ㅇㅇㅇㅇ 모호하면 다운로드 ㄱㄱ", "음 우선 파일 저장 선택창 있을거라 브라우저에 우선 메몬하고 따로 추가ㅎ하지ㅁ말자. 중간에 깼다 ㅅㅂ ㅣㅇ엉서 해". 파일 경계 보강에 대한 코어 수정 승인: "ㅇㅇ 그건 건드려야지. 리스크없으려나? 그리고 프로젝트 밖이면 뭐 안되는거야??" |
| D-13 | Explorer는 왼쪽 사이드바가 아니라 오른쪽 패널에 그린다. 코어가 이미 `RightPanelSection::Explorer`로 모델링하고 Swift가 `RightPanel`에 그리므로 상태 이름과 화면 위치를 일치시킨다. 왼쪽 유지(b)와 양쪽 토글(c, 코어에 새 레이아웃 상태 필요)은 기각. | 라이브 테스트 "Explorer가 원래 우측에 있었는데 그거에 대해서는 없던거? PRD에?" 뒤 "오른쪽으로 옮김 (Swift와 동일)" |
| D-14 | 가정: 미저장 버퍼의 신원은 (체크아웃 루트, 실경로). 저장 성공·탭 닫기·충돌에서 "다시 읽기"를 고르면 지우고, 리네임·이동은 새 경로로 옮기고, 코어가 문서를 닫았거나 경로가 없으면 폐기하고 진단 로그에 남긴다. 14일 지난 버퍼는 다음 실행에서 폐기. IndexedDB를 못 쓰거나 할당을 넘기면 편집은 계속되고 탭에 "이 탭에서만 유지됨" 배지 하나. 재검토: 사용자가 버퍼 손실을 겪을 때. | 위임 "내가 정해서 넣어 (위임)" |
| D-15 | 원칙 입력: engineering·design 원칙 전체를 읽고 이번 D-12 개정은 기존 스트림 재사용(engineering 7), 무제한 버퍼링 금지(engineering 15), 파일 자리의 실패·복구 표시(design 9·13)로 반영한다. 기존 동작·상한·복구·토큰 요구는 유지한다. 별도 원칙 문구를 제품 요구로 중복 추가하지 않으며 전체 리디자인은 S3 밖이다. | `engineering/principles.md`, `design/principles.md`, 기준 커밋 `654485f96b7764c759662d2c3e9e386ebc221cf6`; Q42 |

## Technical structure

- 전달: `delivery.mode: pr`(agents/config.json). 하나의 PR, 커밋은 단위별(hided 경계·나열·watch / 인덱스 / 첨부 / Explorer / 에디터 / 뷰어 / 팔레트 / 측정·docs). 2026-09-24 마무리 방식은 구현자가 경계 수정·회귀 테스트를 커밋하고 Observer가 diff를 검토한 뒤, PR 필수 CI가 통과한 정확한 HEAD를 머지한다. 별도 로컬 `sasu implement verify`와 반복 하위 리뷰는 생략하며 이전 HEAD의 PASS를 새 HEAD의 증거로 사용하지 않는다. 필수 CI·브랜치 보호와 미해결 파일 경계 결함의 처리 기준은 유지한다. 사용자: "ㅇㅇ 우선 저거 implementor쪽에서 verify 별도로 거치지 않고 수정만하고 너가 검토해서 바로 CI 머지로 가버리게 하자. 지금 넘 오래걸려서 ㅎㅎ" 및 "얼른 마무리하고 S4로 가자 바뀐 방식의 implement와함께 !".
- `hided/`: 경계 필터를 `$HOME` 디렉터리 나열에서 "등록된 체크아웃 루트 아래" 파일 경로 검사로 확장(S2 `boundary.rs` 확장, 스냅샷의 체크아웃 목록이 루트의 출처). 새 서버 프레임: 디렉터리 나열(파일 포함), 변경 통지(watch), ⌘P 인덱스 결과, 첨부 저장 결과, 파일 바이트 읽기(이미지·PDF·비디오를 같은 경계 검사 뒤 WS 바이너리 프레임으로 스트림; 비디오는 탐색을 위해 범위 읽기). 상한 초과 파일 다운로드도 기존 `file_bytes`를 재사용하며, 일반 브라우저 WS의 기본 앱 열기 요청은 로컬 신뢰를 입증하지 못하므로 거부한다. 네이티브 통합은 후속이며 이 변경으로 새 신뢰 전달 경로나 HTTP 엔드포인트를 추가하지 않는다. 첨부 바이트는 기존 토큰 게이트 WS의 바이너리 프레임으로 받는다(S1 D-03 유지). 감시·인덱스는 상한을 가진 hided 소유 자원이며 클라이언트가 떠나면 해제된다.
- `web/`: Explorer(react-virtual 트리, 컨텍스트 메뉴, 인라인 입력, 드래그 이동), 에디터(CodeMirror 6 + 언어팩 lazy, 찾기, wrap, 글자 크기), Markdown Live, pdf.js, 이미지 뷰어, ⌘P/⌘K 팔레트, 첨부 드롭/붙여넣기, IndexedDB 버퍼. 상태는 zustand 스토어 셀렉터로만; 문서 권위는 코어.
- `herdr-core`: `MAX_EDITABLE_BYTES`를 2 MiB에서 16 MiB로 올리고, 기존 파일 읽기·저장·생성·이동·휴지통 작업이 검증된 루트·대상에 묶여 실행되도록 필요한 경계 보강을 허용한다(D-01, D-12, B11). 이 예외는 파일 작업 경계에만 적용하며 새 제품 기능이나 웹 전용 병렬 파일 구현을 추가하지 않는다. 기존 Swift 호출자와 이벤트·스냅샷·C ABI 계약은 유지한다. 자동저장은 웹이 기존 `file_save`를 스스로 보내는 것이고 코어에 새 이벤트는 없다. `contracts/hided-ws.schema.json`에 프레임·이유 코드 추가.
- 프로세스 경계는 S1 그대로(브라우저 ↔ hided 루프백 WS ↔ Herdr 소켓 / 코어).

## Risks

- 경계가 "등록된 체크아웃 루트"로 넓어지므로 루트 목록의 출처(스냅샷 체크아웃)가 바뀌는 순간(등록 해제, 워크트리 제거) 진행 중 나열·watch가 남지 않아야 한다. hided가 루트 변경마다 자원을 재검토하고, Security 리뷰가 링크·`..`·인코딩·레이스 우회를 S2와 같은 목록으로 공격한다.
- 첨부 바이트가 WS를 타므로 20 MiB 프레임이 스냅샷 델타와 같은 소켓을 지난다. 프레임 분할 또는 별도 WS 연결로 델타 지연이 S0 게이트를 넘지 않는지 B16으로 측정한다.
- watch·인덱스는 hided 자원이라 여러 브라우저 탭이 붙으면 중복될 수 있다. 체크아웃별로 하나만 만들고 클라이언트 수를 참조로 센다(engineering 14·15).
- Markdown Live의 PR #110 동작 목록은 Swift 구현에 있으므로 옮길 때 누락이 생길 수 있다. 목록을 e2e 케이스로 옮기고 빠진 것은 Follow-up으로 기록한다.
- 다운로드 지원 경계: 256 MiB 초과 파일에는 파일 저장 선택창이 필요하다. 일반 웹의 loopback 주소는 같은 기기의 증명이 아니며 브라우저 요청으로 호스트 기본 앱을 실행하지 않는다. 취소·미지원·전송 실패는 B4대로 다루며 무제한 메모리 폴백이나 새 HTTP 다운로드 경로를 추가하지 않는다.
- 라이브 검증 경계: 구현자는 격리 Herdr + 임시 체크아웃만. 실사용 관찰(B19)은 사용자가 한다. 사용자가 할 일은 B19 외에 없다.
