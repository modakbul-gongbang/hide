# PRD: Overview 요청 보기: 시킨 일, 결과, 내가 할 일을 한 화면에

## Goal

여러 pane에 일을 맡기는 hide 사용자는 지금 Needs You나 done이 뜰 때마다 pane에 하나씩 들어가야 그 세션이 무슨 일을 하는지, 내가 무엇을 시켰고 어떻게 됐는지, 내가 무엇을 하면 되는지 알 수 있다.
이 변경 후 Overview의 첫 화면은 에이전트마다 세션 목표, 내가 시킨 말, 결과 또는 질문 한 줄, 열어 볼 링크, 지금 내가 할 일(답할 것, 고칠 것, 리뷰·머지, 멈춤, 결과 볼 것)을 한 목록으로 보여주고, 이 화면은 Claude Code, Codex, OpenCode에서 같게 동작하며 AI를 꺼도 원문으로 선다.
2026-10-01 진단에서 지금 Overview는 산출물(에이전트 그래프, 이슈, PR) 기준이라 거의 보지 않게 됐고, 2026-10-02 살아 있는 pane 22개로 만든 HTML 프로토타입에서 레이아웃 A(동사별 받은편지함)를 골랐다.
같은 조사에서 Codex 0.157의 공유 데몬 때문에 Herdr가 Codex pane의 세션을 알 수 없어 Codex 행이 아무것도 읽지 못하는 것과, 지금 라벨의 task가 작은 단계로 미끄러져 진행 줄과 겹치는 것이 드러났고, 이것도 함께 고친다.

## Non-goals

- PR 본문에 이슈 번호만 적은 관련 이슈는 잇지 않는다(D-44). 그 이슈 카드에는 그 PR이 보이지 않는다. 재검토: 따로 여는 Issues·PRs 보드 이슈에서 다룬다.
- 목록에서 바로 답하지 않는다(D-28). 답은 열기로 간 pane에서 한다. 재검토: 답하러 pane에 들어가는 비용이 반복해서 불만이 될 때.
- 폰 동반 앱(/m/), 알림, 푸시, dock 배지는 바꾸지 않는다. 폰에서는 지금처럼 에이전트 목록과 대화를 본다. 재검토: 폰이나 알림에 요청·결과 한 줄을 원할 때.
- Agents 그래프, Issues·Tasks, PRs, Sessions 보기 자체는 바꾸지 않는다(D-04). dependabot PR 접기나 PR 행에 결과 붙이기는 하지 않는다. 재검토: PR 탭의 잡음이 요청 보기로도 해결되지 않을 때.
- 요청 보기에는 필터, 검색, 정렬 컨트롤이 없고 순서는 D-06 묶음과 D-40 순서로 고정이다. 재검토: 행이 늘 한 화면을 넘을 때.
- Claude Code, Codex, OpenCode 밖의 에이전트는 기록을 읽지 않고(L0), 에이전트가 스스로 요청·결과를 보고하는 공개 계약(pane 토큰 등)은 만들지 않는다(D-16). 재검토: 네 번째 에이전트를 붙여 달라는 요청.
- 에이전트 자체 하위 세션(Claude subagent, OpenCode 하위 세션)과 diff 통계 같은 추가 정보를 따로 그리지 않는다(D-15). 재검토: 부모 행에서 자체 하위 작업을 보고 싶다는 요청.
- Codex 공유 데몬을 켠 채로 Codex pane을 읽지 않는다. upstream openai/codex#48500 전에는 방법이 없어, Codex 항목을 끈 사용자가 손으로 친 Codex 행은 L0이다(D-24, D-26). 재검토: #48500 해결.
- 떠 있는 Codex 데몬을 멈추지 않고, 사용자 셸의 alias, 함수, preexec, 래퍼를 건드리지 않는다(D-22, D-23). 데몬이 내려갈 때까지 운영자가 손으로 친 Codex는 데몬에 붙어 L0이다. 재검토: 데몬 정지를 hide에 맡기고 싶다는 요청.
- 폴더와 시각으로 세션을 추정하지 않고 글 패턴으로 요청자를 추정하지 않는다(D-17, D-19). hide 밖(Herdr 자체 화면, ssh 터미널)에서 직접 친 입력은 에이전트가 넣은 말로 보인다. 재검토: Herdr가 입력의 보낸 이를 알려 주게 될 때.
- 세션 목표가 바뀌어도 이전 목표를 보관하거나 보여 주지 않는다(D-38). 재검토: 한 세션의 목표 변천을 보고 싶다는 요청.
- 답이나 명령에 PR이 언급됐다는 이유로 행에 PR을 잇지 않는다(D-31). 그 PR은 열 것 칩으로만 보인다. 재검토: 만들지 않은 PR을 맡아 이어 가는 세션이 흔해질 때.
- PRD·quick slug나 브랜치로 일을 묶지 않는다(D-01). 같은 일을 하는 에이전트 여럿은 각자 한 행이다. Overview 전체를 요약하는 AI 문단을 두지 않는다(가정: 행과 겹치고 금방 낡는 문장 배너, design/principles.md 7, 13). 재검토: 행을 일 단위로 묶을 공통 키가 모든 사용자에게 생길 때.
- 워크트리 이름 짓기와 Project Memory의 AI 스위치를 하나로 모으지 않는다(D-11). 그 둘은 지금 자리(Settings › Issues, 프로젝트별)에서 따로 끈다. 재검토: Background AI 전체를 한 번에 끄고 싶다는 요청.
- device 프로젝트의 PR은 잇지 않는다. 지금 PR 읽기가 이 Mac의 로컬 Git 프로젝트만 하므로 device 행에는 PR 동사가 없다. 재검토: device 프로젝트의 PR 읽기가 생길 때.
- 기존 사용자 설정을 옮기는 마이그레이션은 없다(D-27). 이미 데몬에 붙어 있는 Codex는 다시 열어야 읽힌다. 재검토: 이 Mac 밖의 기존 사용자가 생길 때.

## Decisions

| --- | --- | --- |
| D-01 | 화면의 단위는 운영자가 에이전트에게 친 요청 하나(에이전트 행)다. PRD·quick slug나 브랜치로 일을 묶는 안은 기각한다. | 사용자: "agents/prd 이거는 내가 그러는거고 사용자는 다를수도 있잖아" |
| D-02 | 목표는 pane에 들어가지 않고 각 에이전트에게 무엇을 시켰는지, 어떻게 됐는지, 내가 무엇을 확인하면 되는지를 한 화면에서 보는 것이다. | 사용자: "여러작업시켰을 때 내가 뭘시켰는지 + 어떻게 되고있는지 그걸 한눈에보고싶긴하거든? ... 나는 뭘 확인하면 되는지가 중요한데" |
| D-03 | 레이아웃은 A(동사별 받은편지함)다. 상태별 보드(B, Orca 칸반과 같음)와 사이드바 강화(C, Paseo와 같음)는 기각한다. | 사용자: "A로 해야지 ㅇㅇㅇ". Orca·Paseo 코드 조사(둘 다 상태 이름까지만 보이고 턴 결과 요약, 할 일 계산, 위임 요약이 없다). |
| D-04 | PR·Issue·Sessions 보기는 산출물 보기로 그대로 두고, Agents 그래프는 별도 재작업 몫이라 이 PRD는 바꾸지 않는다. | 사용자: "PR / Issue 베이스대로 보는건 또 그거대로 한눈에 조감하기에 괜찮은 것 같기는 한데?", "agent graph를 다시 수정하게 하는게 있고" |
| D-05 | 요청 보기는 프로젝트 Overview의 첫 타일 `요청`이자 모든 프로젝트 Overview의 첫 탭 `요청`이고, 두 Overview로 들어가는 모든 길이 이 보기로 연다(Recent Panels 복원 제외). 지금의 첫 화면(프로젝트: Agents 그래프, 모든 프로젝트: Tasks)은 탭으로 남는다. | 가정: "Overview를 잘 안 보게 된다"는 사용자 첫 메시지에 대한 답이 첫 화면이어야 한다. agents-graph-view B1의 진입 규칙을 바꾸므로 사용자 검토 대상이다. |
| D-06 | 묶음과 순서는 답할 것, 고칠 것, 리뷰·머지, 멈춤, 결과 볼 것, 일하는 중, 기다리는 중, 쉬는 중(접힘)이다. 빈 묶음은 그리지 않는다. | 가정: 프로토타입에서 보여준 순서. 프로토타입에서 진행 중 12개 중 5개가 실제로는 CI나 자식을 기다리고 있어 일하는 중과 기다리는 중을 나눴다. |
| D-07 | 동사는 core가 Herdr 상태, hide의 읽음·요구 축, 연결된 PR의 상태와 CI, 계보로 계산한다. AI는 글로 쓴 질문, 멈춤, PR이 아닌 기다림만 보탠다. AI가 "지금 할 일"을 정하는 안(v4 check)과 AI가 PR 번호를 짚는 안(v4.1 pr)은 기각한다. | v4 평가(살아 있는 pane 17개): 기다림 판정 9개 중 3개가 한 시간 안에 틀렸고 review는 16개 중 0개였다. 사용자: "어어 그렇구나 우선 이 상태에서 더해서 좀 더 이야기해보자". PR 번호는 D-31로 AI에서 뺐다. |
| D-08 | AI 출력은 세 필드(v5)다: goal(세션 목표, D-38), line(일하는 동안은 이번 턴에 하는 일, 끝나면 그 결과, 질문으로 끝났으면 운영자가 답하거나 할 일, 40자 이내, goal을 되풀이하지 않음), end(working, question, done, waiting, unfinished). v4.1의 task는 goal로 바뀌고, ask는 질문일 때의 line으로, pr은 AI 밖의 PR 연결(D-31)로 옮긴다. v3의 progress·attention·expected_reply도 이 셋으로 합친다. | 사용자: "실제로 내가 필요한거는 이 세션이 전체적으로 무슨작업을 하는건지인데 ... task만 봤을때 좀 헷갈리기도 하는 것 같아 progress랑 약간 겹칠때도 잇고?". 세 필드 제안(ask는 line으로, pr은 AI 밖으로) 뒤 "ㅇㅇㅇ 그러면 최종 PRD 정리해봐". |
| D-09 | AI 호출 횟수는 그대로다: 턴 하나에 턴 시작 1회와 턴 끝 1회, 턴 끝 호출이 시간 초과일 때만 1회 더(D-33). goal은 새 운영자 요청이 온 턴 시작(또는 아직 goal이 없는 첫 분석)에서만 다시 판정하고, 턴 끝은 line과 end만 쓴다. 입력은 운영자 요청만(첫 3개와 최근 8개, 위임받은 자식은 부모가 맡긴 첫 요청 포함), 직전 goal, 마지막 주고받음이며 상한 4000자는 그대로다. 턴 사이의 변화는 Herdr 상태와 PR/CI가 AI 없이 반영한다. | 사용자: "AI 실행 횟수는 어떤 것 같아 충분해보여?"에 대한 답 뒤 "어어 그렇구나". 2026-10-02 목표 실험: 첫 요청을 빼고 최근 요청만 넣으면 이 세션의 목표가 옆길 Codex 질문으로 두 번 바뀌었고, 첫 3개를 늘 넣자 바뀌지 않았다. 목표는 새 요청이 올 때만 판정한다는 설명 뒤 사용자: "ㅇㅇ". |
| D-10 | AI는 애드온이다. AI 꺼짐, AI 실패, 사용량 한도는 모두 같은 화면이고, 화면은 AI 없이 원문과 core 계산만으로 선다. | 사용자: "ai 기능을 사용자가 껐다(끌수있게 해야할듯? 나중에) 그럴때 어케보일거냐는 이야기임. addon 느낌으로 가져가고 싶어서 ai 기능들은" |
| D-11 | Settings › Background AI에 `에이전트 요약` 스위치(기본 켬, 이 Mac 설정)를 둔다. 끄면 라벨 AI 요청이 멈추고 AI 필드가 모든 화면에서 사라진다. 다른 AI 스위치를 하나로 모으는 일은 하지 않는다. | 사용자: "끌수있게 해야할듯". labels-in-hided Non-goal의 재검토 조건("기기별로 AI 비용을 끌 필요가 생기면 Settings 항목으로"). 통합 제외는 가정(범위). |
| D-12 | AI가 없는 행의 칸: 제목은 에이전트 자체 제목(Claude `ai-title`, Codex `thread_name`, OpenCode `session.title`), 없으면 provider 이름이다. 요청 줄은 마지막 운영자 요청의 원문을 D-42 규칙으로 한 줄에 줄인 것이다. 결과 줄은 일하는 동안 마지막 assistant 말의 원문, 끝나면 그 말의 마지막 줄 원문이다. | 제안 표(칸별 AI 꺼짐과 켬) 뒤 사용자: "ㅇㅇㅇ claude code는 그런데 이제 다른 에이전트들(codex, opencode 등등) 은 어케되냐가 중요한거지" |
| D-13 | 이름 사다리는 모든 화면에서 goal, 에이전트 자체 제목, provider 이름 순이다. status-model의 "ai-title을 읽지 않는다" 규칙은 이것으로 대체한다. | 가정: 한 에이전트는 모든 화면에서 같은 이름이라는 기존 규칙(docs/status-model.md Task identity)을 지키려면 요청 보기만 다른 이름을 쓸 수 없다. 사용자 검토 대상이다. |

## Technical structure

`hide-session`에 에이전트 중립 세션 어댑터를 두고 Claude, Codex에 더해 OpenCode(rusqlite 읽기 전용)를 읽는다.
어댑터는 자체 제목, 사람 입력 기록과 시각, 마지막 assistant 말과 그 안의 열 수 있는 대상, 도구 출력에 찍힌 PR 주소와 그 시각, 턴 경계, AI 입력 이벤트를 한 모양으로 내고, 에이전트 버전별 실제 기록 fixture로 같은 계약 테스트를 통과한다.
요청자 판정에 쓰는 hcoord 봉투 형식은 `plugins/hcoord`와 `hide-session`이 함께 지키는 계약으로 두 쪽에 계약 테스트를 둔다.
core는 터미널 입력 경로(로컬 pane, 폰의 pane 입력, device 키 입력)에서 운영자의 제출을 pane별로 시각과 함께 상한 있는 메모리 기록으로 남기고, 어댑터가 읽은 사람 입력을 짧은 시간 창으로 맞춰 요청자를 정한다.
정해진 요청자, pane별 입력 관찰 시작 시각, goal, 동사가 된 시각은 세션 사실로 `labels.json`에 함께 보관한다.
`herdr-core/src/labels/` worker가 지금의 트리거와 상한 그대로 어댑터로 읽고, device는 `hide-host-helper`의 읽기 호출이 그 기기에서 어댑터를 돌려 정규화 결과를 돌려준다. helper protocol 버전이 오른다.
라벨 프롬프트와 schema는 `context_label` v5(goal, goal_changed, line, end)로 바뀌고 v3는 지운다. AI 스위치는 hide-ai 설정에 저장되며 worker가 분석 전에 확인하고 overlay가 꺼진 동안 AI 필드를 숨긴다.
core가 에이전트 행마다 동사를 계산해 스냅샷에 싣는다. 재료는 기존 group·demand·읽음 축, 계보, 브랜치별 PR 답과 그 세션이 만든 PR(D-31, 기존 PR 목록 요청에 `createdAt` 필드를 더해 판정)로 찾은 같은 저장소의 PR, AI end다. 스냅샷 agent row에 동사와 그 시각, 자체 제목, 요청 줄과 요청자, 결과 줄, 열 것 목록이 더해져 snapshot wire 계약이 바뀐다.
Overview에서 결과를 연 것은 새 이벤트 하나로 pane 읽음 기록을 갱신한다. 요청 보기가 화면에 있음을 shell이 core에 알리면 core는 CI 진행 중 PR이 연결된 저장소만 60초마다 기존 GitHub worker의 세대를 올리고, `gh`는 runtime 잠금 밖에서 돈다.
web은 `ProjectOverview`와 `MainScreen`에 요청 보기와 타일·탭을 더하고 진입 탭을 바꾸며, 열 것 칩은 기존 터미널 링크 열기 경로를 쓴다. 행은 docs/DESIGN_WORKFLOW.md 절차로 Pen library의 Component가 된다.
`hide-kit`에 새 구성요소(Codex를 pane마다 실행)를 더하고 운영자가 끈 상태를 kit 기록에 남기며, 실제 `codex features` 실행은 `hide-agent-hooks`가 시간 제한과 함께 한다. Settings 줄에는 이 항목에만 끄기·켜기가 있다.
core의 Codex 실행 인자는 함수 하나가 만들어 모든 경로(작업 시작, 다시 열기, fork, 깨우기)가 쓰고, 그 기계의 Codex가 옵션을 지원하는지는 kit의 버전 확인 결과를 쓴다. hcoord의 Codex 인자와 저장소의 sasu dispatch 인자도 같은 판단을 한다.

## Risks

- 한 PR이 core, hide-session, helper protocol, kit, hcoord, web을 함께 바꾼다. D-36 순서로 쌓고, 리뷰는 runtime 잠금 아래 I/O 없음, snapshot wire, helper protocol, 운영자 설정 쓰기, 스냅샷 발행 빈도, 키 입력 경로에 더한 일을 본다.
- 운영자 입력 기록은 키 입력이라는 고빈도 경로에 놓인다. 제출(Enter)만 시각으로 남기고 입력 글자는 남기지 않으며, pane별 기록은 상한을 둔다.
- 운영자가 Enter를 누른 직후 다른 에이전트의 입력이 같은 pane에 들어오면 운영자 요청으로 셀 수 있다. 시간 창을 짧게 두고, 하나의 제출에 두 기록이 맞으면 진단에 남긴다.
- kit 항목은 운영 자동화가 도는 mini를 포함한 모든 등록 기기의 Codex 동작을 바꾼다. 데몬 기능(`codex agents`, remote-control)에 기대는 자동화가 있으면 새로 여는 Codex부터 그 기능이 빠진다. 지금 mini의 Codex는 0.155.1이라 해당 없음이지만, 이 기능이 든 빌드를 mini에 설치하기 전 그곳의 Codex 데몬 의존을 확인하는 것은 운영자 몫이다.
- Claude `ai-title`, 도구 실행 기록 등 에이전트 기록 형식은 문서화되지 않아 예고 없이 바뀔 수 있다. 계약 fixture가 깨지면 그 에이전트 행은 L0으로 떨어지고 진단이 남는다.
- OpenCode 데이터베이스 schema와 잠금은 OpenCode 버전마다 다를 수 있다. 읽기 전용, 짧은 대기, 건너뛰기로 OpenCode 동작을 해치지 않는다.
- goal 한 번의 판정은 흔들릴 수 있다(같은 입력에 세 번 물어 세 가지 이름이 나온 사례가 있다). 직전 goal을 들고 바뀔 때만 바꾸는 규칙(D-38)과 새 운영자 요청에만 판정하는 규칙(D-09)이 화면을 안정시킨다.
- 요청 줄, 결과 줄, 열 것 목록의 원문이 스냅샷으로 web에 간다. 같은 Mac의 화면이고 pane에서 이미 보이는 글이지만, 폰으로 가는 데이터에 섞이지 않는지 확인한다. device 기록은 SSH로 와서 메모리에서만 쓰고, AI 입력은 기존 마스킹(비밀, 이메일, 홈 경로)을 거친다.
- 턴 끝 재시도로 AI 호출이 실패한 턴마다 최대 1회 늘고, 이는 기존 `one_turn_costs_at_most_two_provider_calls` 상한을 바꾼다. 60초 PR 다시 읽기는 요청 보기가 열려 있고 CI가 진행 중인 저장소에만 한다. 기본 모델 sonnet(D-41)의 사용량은 출력 토큰으로만 어림했고 사용량 창으로는 재지 않았다.
- PR을 만든 세션을 hide가 읽지 못하고(pane이 닫혔거나 다른 기기) 다른 세션 하나만 30초 안에 같은 주소를 찍었으면 그 세션에 PR이 잘못 붙는다. 측정한 128개에서는 없었고, 붙어도 그 행의 PR 칩 하나가 틀릴 뿐 데이터나 다른 행은 바뀌지 않는다.
- 사용자 검토가 필요한 가정: 진입 화면을 요청 보기로 바꾸는 것(D-05, agents-graph-view B1 변경), 이름 사다리를 모든 화면에서 바꾸는 것(D-13), 펼치면 읽음이 되는 것(D-29), 자식을 부모 행에 접는 것(D-30), AI 스위치를 이번에 넣는 것(D-11), PR을 "만든 세션"으로 잇는 것과 30초, 할 일을 한 행에 두는 규칙(D-31), 여러 PR·이슈를 한 행에 칩 하나와 `+N`으로 보이는 순서(D-46), 열 것 칩 3개와 그 대상 종류(D-39), 긴 요청을 앞 + 끝으로 줄이는 규칙과 그 수치(D-42).
- 검증은 격리 HOME, 격리 CODEX_HOME, 격리 Herdr, 합성 대화 기록, 결정적 provider로 하고 운영자의 앱, Herdr 서버, `~/.codex`, AI 로그인은 쓰지 않는다. Codex 0.157 이상과 옛 버전, OpenCode가 있는 기계와 없는 기계를 모두 본다.
- 이 Mac은 이미 손으로 적용했으므로 구현 전에 사용자가 할 일은 없다.
