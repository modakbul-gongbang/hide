# PRD: hide mobile companion

## Goal

맥에서 여러 에이전트를 돌리는 hide 운영자가 자리를 떠나 있어도 폰으로 어떤 에이전트가 자기를 기다리는지 보고, 그 에이전트의 터미널을 읽고, 짧은 답이나 키 하나로 바로 답할 수 있게 한다.
운영자는 hide 설정 > Mobile에서 QR을 찍어 자기 Tailscale tailnet 안에서만 열리는 hide 웹앱(PWA)을 폰 홈 화면에 두고, 선택하면 Needs You·Done 전이 때 푸시를 받는다.
지금 필요한 이유는 에이전트가 권한 프롬프트나 질문에서 멈춘 채 운영자가 맥 앞에 돌아올 때까지 기다리는 시간이 병렬 작업의 가장 큰 손실이기 때문이다.

## Non-goals

- 네이티브 앱(App Store, TestFlight, 사이드로드)은 만들지 않는다. 폰 앱은 홈 화면 PWA뿐이다. 서명 배포가 필요한 기능(백그라운드 실행, 위젯)이 요구될 때 다시 본다. (D-02)
- hide가 터널이나 릴레이 서버를 번들하거나 운영하지 않는다. Tailscale이 없는 운영자는 이 기능을 쓸 수 없다. 전송 경계 세 개(QR 형식, /ws 전용, 프레임 인코딩 한 함수)만 준비하고, 릴레이 요구가 생기면 Tailscale 모듈을 지우고 릴레이 모듈을 더한다. (D-01)
- 전체 터미널 키보드·IME, 사진 첨부, 받아쓰기, 파일 트리, diff, 커밋·PR 작업은 폰에 없다. 폰의 일이 "기다리는 에이전트에 답하기"를 넘어설 때 다시 본다. (D-03)
- 여러 맥을 한 PWA에서 전환하지 않는다. 맥마다 자기 ts.net 주소의 홈 화면 아이콘이 따로 생긴다. (D-14)
- 맥 입력 유휴 시간이나 데스크톱 포커스로 푸시를 억제하지 않는다. 3단 모드만 있다. (D-09)
- 실제 tailnet과 실제 iPhone으로의 확인은 merge 조건이 아니며 설치 후 운영자 확인이다. (D-11)
- 폰은 파일 열기, 설정, 프로젝트·기기 변경, 전체 스냅샷, 파일 내용을 받지 않는다. (D-04)

## Decisions

| D-01 | 전송 v1은 운영자 자신의 Tailscale이다. hided는 루프백에만 바인드하고 `tailscale serve`가 `https://<mac>.<tailnet>.ts.net`을 Tailscale 인증서로 노출한다. 릴레이 대비 경계: QR 내용 `{v:1, endpoint, code}`와 전송에 무관한 폰 자격증명, 폰 클라이언트는 /ws 메시지만 사용, WS 프레임 인코딩은 한 함수 뒤(이후 E2E 암호화가 감싸고, QR v:2가 호스트 공개키를 더한다). Tailscale 전용 코드(탐지, serve, 체크리스트 내용)는 전송 모듈 하나에만 둔다. 번들 터널·릴레이는 기각. | qa D-07; Q4 "설계할때 tailscale 나중에 걷어낼 수 있는걸 고려해야한다!"; 사전 요청 "우선 Tailscale 하고 나중에 Relay로 바꿔도 상관없겠지" |
| D-02 | 폰 클라이언트는 QR로 열고 홈 화면에 추가하는 PWA다. 네이티브 배포는 기각. | qa D-08; Q1 "앱이 아니라 web으로 우선 들어가는거지?", Q2 확인 |
| D-03 | 폰 v1 범위: 에이전트 상태 목록(이 맥과 연결된 SSH 기기 전체), 선택한 pane의 읽기 전용 스크롤백, 한 줄 답장과 퀵키(Enter, Esc, ↑, ↓, Ctrl-C), 푸시. 전체 터미널 입력, 첨부, 받아쓰기, 파일, diff, 커밋은 제외. 상태는 core의 기존 Needs You/Done/Working/Seen 투영(docs/status-model.md)을 재사용한다. | qa D-09, D-05; Q1 "1,2,3,8 까지 괜찮은 것 같은데" |
| D-04 | 페어링 코드는 5분 1회용이고 QR을 다시 열거나 새 코드를 누르면 새 코드가 나온다. 페어링된 폰은 전용 자격증명을 받아 hided의 0600 상태에 보관되어 재시작·포트 변경을 견딘다. 범위: 상태 읽기, 선택한 pane 스크롤백 읽기, 선택한 pane에 텍스트·키 쓰기, 푸시 구독. 파일 열기·설정·프로젝트·기기 변경은 거부. 만료 없음, 단 7일 동안 접속이 없으면 자동 해지, 설정에서 수동 해지, 최대 4대. | qa D-10; Q2 "QR 페어링 코드는 5분 1회용 ㅇㅇ 좋음 ... 토큰 만료는 7일 미접속시 자동해지 좋다" |
| D-05 | Tailscale 설치·로그인 안내를 눈에 띄게: 설정 > Mobile에 순서 있는 체크리스트(맥에 Tailscale CLI, 로그인, tailnet MagicDNS+HTTPS, 폰에도 Tailscale 같은 계정)를 보이고 첫 실패 단계를 정확한 조치와 함께 강조한다. 넷째 단계(폰)는 hide가 확인할 수 없는 안내 단계로 QR 조건이 아니다(qa Q3 "QR 옆에 항상 표시"): 맥 세 단계가 통과하기 전에는 대기 표시, QR이 나타나면 승인된 보드대로 완료 표시로 바뀌어 지금 폰에서 할 일로 읽힌다. 폰이 tailnet 밖이면 폰 쪽에 연결 안 됨 줄(B23)이 보인다. | qa D-11; Q2 "tailscale 설치해야한다는 거 꼭 잘 안내해줘야겟네" |
| D-06 | Mobile은 기본 꺼짐. 켜면 hide가 직접 `tailscale serve --bg <hided 포트>`를 실행하고 끄거나 hided가 종료할 때 자기가 추가한 항목만 지운다. 포트가 바뀌면 다시 적용한다. 탐지는 macOS 앱 번들 CLI(`/Applications/Tailscale.app/Contents/MacOS/Tailscale`) 또는 PATH의 `tailscale`로 `tailscale status --json`(로그인, DNSName, CertDomains)을 읽는다. QR은 모든 단계 통과 후에만, ts.net 주소와 함께 보인다. 사용자가 명령을 치는 방식은 기각. | qa D-12, D-02; Q3 "ㅇㅇ 그대로 hide가 직접 켜고 끄는걸로" |
| D-07 | hided는 자기가 기록한 serve 항목만 소유한다. 켤 때 `tailscale serve status --json`을 먼저 읽고, HTTPS 포트에 기록 없는 항목이 있으면 기존 대상을 보여 주며 거부하고 QR을 보이지 않는다. 기록 `{dns_name, port, added_at}`은 hided 상태에 두고 시작할 때마다 대조한다(일치: 유지, 옛 포트: 그 기록 항목만 교체, 없음: 다시 추가, Mobile 꺼짐: 남아 있으면 제거). 끄기·정상 종료는 기록 항목만 제거하고 크래시는 다음 시작의 대조에 맡긴다. serve 명령 실패는 Mobile을 "노출 안 됨"으로 두고 QR 없이 실패 단계 한 줄을 보이며 명령과 stderr를 `mobile_transport` 기록으로 Logs/core.jsonl에 남긴다. QR은 serve status가 기록 항목을 확인한 뒤에만 보인다. | qa D-23 (gap-audit 보완, 에이전트 결정) |
| D-08 | 폰 화면은 목록 → 상세 2단 스택이다. 목록은 Needs You / Done / Working / Seen 순 그룹(행: 상태 마크, 프로바이더, 작업명, 프로젝트·브랜치, SSH 기기 칩, 경과 시간), 상세는 같은 머리, 읽기 전용 스크롤백(위로 당기면 더), 답장 바(한 줄 입력 + 보내기, 그 위 퀵키 행). 푸시 탭은 상세로 연다. 프로젝트 보드(B안)와 사이드바 트리(C안)는 기각. 화면은 사용자가 승인한 Pen 보드(agents/runs/mobile-companion/design/board-v2.pen)를 따른다. | qa D-13 + Addendum; Q4 "A로 우선 ㄱㄱ"; 보드 승인 "와 좋네. 충분한 것 같아. 우선 이거 승인 다 됏고" |
| D-09 | 푸시 모드는 설정 > Mobile의 3단 선택: 끔(기본) / 앱이 닫혀 있을 때만(데스크톱 셸이 hided에 연결돼 있지 않을 때) / 항상. Needs You 진입과 Done 진입에서만, 루트 에이전트당 하나(자손의 요청은 루트로 올림), 다음 전이에서 교체, 제목은 작업명, 본문은 상태(승인된 보드의 푸시 배너대로 프로젝트 이름을 곁들임), 터미널 내용 없음. 폰이 그 에이전트 상세를 보고 있으면 보내지 않고, 데스크톱이 Seen으로 만들면 지운다. 실패는 로그에만, 무효 구독은 버리고 다음 접속에서 다시 만든다. orca식 항상 발송 기본값과 유휴 2분 억제는 기각. | qa D-14; Q7 "우선 알림은 따로 안오게해줄 수 있어? 아니면 hide가 안켜져있으면.. 보내게?"; Q8 "ㅇㅇ 그대로 ㄱㄱ" |
| D-10 | Mobile이 켜져 있고 폰이 1대 이상 페어링돼 있으면 hided는 마지막 클라이언트 뒤 idle 종료를 하지 않는다. Mobile을 끄거나 마지막 폰을 해지하면 10분 idle 종료로 돌아간다. | qa D-15; Q8 "ㅇㅇ 그대로 ㄱㄱ" |
| D-11 | 완료 증명은 자동이다: 디버그 hided를 상대로 iPhone 크기 Playwright e2e(페어링, 4그룹, 상세 스크롤백, 답장·퀵키가 pane에 도달, 7일 해지, 4대 상한), fixture PATH의 가짜 `tailscale`로 체크리스트 4상태, 루프백 가짜 푸시 엔드포인트로 페이로드와 3단 규칙. 단위 테스트: serve 추가·제거·포트 변경·종료 정리, 자격증명 범위 거부, VAPID 서명. 실제 tailnet iPhone 확인은 설치 후 운영자 몫이다. | qa D-17; Q9 "ㅇㅇ 자동으로 ㄱㄱㄱ" |
| D-12 | 설정 탭 이름은 Mobile(화면 문구 모바일), 페어링된 대상은 "폰"이며 UI·코드 어디에서도 device라 부르지 않는다(device는 SSH 기기). PWA 이름은 hide. 문구는 승인된 보드의 한국어를 쓴다. | qa D-18, D-04 (가정, 보드 검토로 확인) |
| D-13 | 가정: 폰의 pane 읽기·쓰기는 core의 attach 집합이나 `Event::Key`를 거치지 않고 hided가 Herdr 소켓 API를 직접 호출한다. 읽기는 `pane.read`(`source: recent`, 줄 수 한정), 쓰기는 `pane.send_input`(text와 keys)이며 메서드와 인자는 `contracts/herdr-api.schema.json`으로 확인한다. 연결된 SSH 기기의 pane은 core가 그 기기에 이미 가진 Herdr API 연결로 같은 메서드를 부른다. qa D-19의 "attach 집합에 읽기 전용 capture로 합류" 가정은 재검토 조건(데스크톱의 보이는 탭과 ATTACHED_TAB_LIMIT을 건드리지 않을 수 없음)이 성립해 대체한다: attach 창은 공유되고 `key`는 전역 focus를 옮긴다. | qa D-19 재검토 조건; research §3 |
| D-14 | 가정: 맥 하나당 PWA 하나. 두 번째 맥은 두 번째 QR이다. 폰 연결은 MAX_CLIENTS=8에 포함되고 4대 상한이 데스크톱 자리를 남긴다. | qa D-20 |
| D-15 | 새 화면은 docs/DESIGN_WORKFLOW.md를 따른다. 승인된 보드를 `design/hide-screens.pen`의 `Screen / Mobile` 시트로 옮기고(`scripts/pen-screens.mjs` 빌더 + `node scripts/gen-screens.mjs`), library 토큰과 System 파트를 쓰며 `node scripts/check-design-contract.mjs`를 통과한다. | qa D-21 + Addendum |
| D-16 | 정적 셸과 런타임 데이터를 나눈다. PWA의 HTML, JS, manifest, 아이콘, service worker는 전송의 HTTPS 출처로 hided의 정적 라우트에서 나온다(v1: `/m/` 아래). service worker는 정적 자산만 캐시한다. 페어링 코드 교환, 상태, 스크롤백, 답장·퀵키, 푸시 구독 등록은 모두 /ws로 오가며 폰 클라이언트는 다른 HTTP 경로를 부르지 않는다. Mobile이 켜진 동안만 허용 Origin에 `https://<Self.DNSName>`이 추가된다. | qa D-22, D-01 |
| D-17 | 목록 행, 상세 선택, 푸시 딥링크는 이름이 아니라 core의 안정 식별자(기기 id + pane id, 루트로 올린 경우 루트 pane id)를 쓴다. 푸시 페이로드는 작업명·상태 옆에 그 id를 싣는다. | qa D-24 |
| D-18 | 답장 바와 퀵키는 상태 그룹과 무관하게 모든 상세에 있다(Working에 Ctrl-C, Done에 후속 지시). Needs You 전용은 기각. | qa D-25; Q10 "1번으로 ㄱㄱ" |
| D-19 | 폰의 푸시 구독은 그 폰 자격증명의 일부다(D-04 범위). 수동·7일 자동 해지는 같은 쓰기에서 구독을 지우고, 해지된 폰으로는 더 보내지 않으며, 다시 페어링한 폰은 새 구독을 /ws로 등록한다. PWA는 자격증명이 거부되면 로컬 구독도 해지한다. | qa D-26 (D-04 범위에서 도출, gap-audit F1 보완) |
| D-20 | 가정: 알림 권한은 폰에서만 묻는다. 푸시 모드가 끔이 아니면 목록 화면에 "알림 켜기" 행이 하나 보이고 탭하면 권한을 요청한다(Safari 탭에서 열렸으면 홈 화면에 먼저 추가하라고 안내). 허용하면 /ws로 구독을 등록한다. 거부되거나 나중에 꺼지면 폰에 "알림이 꺼져 있어요 · 설정 > 알림에서 hide를 켜세요", 설정 > Mobile 폰 행에 "알림 꺼짐"이 보이며, OS에서 다시 켜고 PWA를 열면 재페어링 없이 다시 구독한다. | qa D-27 (위임 하 가정, 거부 가능) |
| D-21 | 가정: 데스크톱이 Seen으로 만든 알림의 제거는 조용한 푸시를 보내지 않고 service worker가 다음에 실행될 때(다음 푸시 도착 또는 PWA 열기) 그 에이전트 태그의 알림을 닫는 방식이다. iOS는 알림을 보이지 않는 푸시를 받은 구독을 끊기 때문이다. | D-09 의도 안의 에이전트 결정 |

## Technical structure

모든 모바일 코드는 hided의 `hided/src/mobile/` 아래에 있고 herdr-core는 폰을 모른다.
- 전송 모듈(Tailscale 전용, 이 파일 하나만 지우면 Tailscale이 빠진다): CLI 탐지, `tailscale status --json`, `tailscale serve --bg <port>` 추가·확인·제거, 소유 기록과 시작 대조, 체크리스트 단계 계산.
- 폰 자격증명: hided 상태 디렉터리의 `phones.json`(0600)에 폰별 자격증명 해시, 이름, 마지막 접속, 푸시 구독을 둔다. 5분 1회용 페어링 코드는 메모리에만 있다. 7일 미접속 해지와 4대 상한을 여기서 집행하며, 해지는 자격증명과 구독을 한 쓰기로 지운다.
- 폰 WS 루프: 기존 `/ws`에서 첫 프레임이 `{token, schema_version, client_kind:"phone"}` 또는 `{pair, client_kind:"phone", name}`이면 폰 루프로 간다. 폰 루프는 core 스냅샷에서 폰 전용 투영(그룹별 에이전트와 안정 id, 파일·전체 스냅샷 없음)만 보내고, pane 읽기·쓰기는 Herdr API(`pane.read`, `pane.send_input`)를 직접 부르며, 원격 pane은 core가 가진 그 기기의 Herdr API 연결을 쓴다. 폰 프레임 인코딩은 한 함수 뒤에 있다.
- 푸시 발송: VAPID 키쌍, RFC 8291 암호화, ureq+rustls로 푸시 서비스에 POST. core 알림을 구독해 루트 에이전트의 그룹 전이를 감지하고 3단 모드와 데스크톱 렌더러 연결 수로 거른다.
- hided는 renderer에 `mobile` 프레임(체크리스트, 노출 상태, QR 내용, 코드 만료, 폰 목록, 푸시 모드)을 보내고 `mobile_*` 이벤트(켜기·끄기, 새 코드, 해지, 푸시 모드)를 받는다. Mobile 설정(켜짐, 푸시 모드)과 serve 기록은 hided 상태에 둔다.
- 폰 켜짐 동안 허용 Origin에 `https://<DNSName>`을 추가하고, Mobile이 켜져 있고 폰이 있으면 idle 종료를 건너뛴다.
- 정적: `web/mobile.html`을 두 번째 Vite 입력으로 빌드하고 hided가 `/m/`, `/m/manifest.webmanifest`, `/m/sw.js`, 아이콘을 기존 정적 경로 규칙으로 제공한다.
- 진단은 `herdr_core::diagnostic!`으로 Logs/core.jsonl에 쓴다(hided의 eprintln은 그 파일에 닿지 않는다).
- Herdr 메서드·인자는 `scripts/check-herdr-contract.sh`와 고정 스키마로 확인하며 새 wire 타입 변환이 필요하면 `herdr-core/src/wire.rs`에 둔다.
- 검증: iPhone 크기 뷰포트와 hasTouch의 Playwright e2e, fixture PATH의 가짜 `tailscale` 스크립트, 루프백 가짜 푸시 엔드포인트, 전송·자격증명·VAPID 단위 테스트.

## Risks

- hided가 tailnet에 노출된다. Tailscale ACL과 페어링 자격증명 두 겹이 경계이며, 폰 자격증명은 쓰기 범위가 선택한 pane 입력뿐이고 파일·설정 변경을 거부한다. 코드와 자격증명은 로그와 서버 요청 줄에 남지 않는다.
- 운영자의 Tailscale serve 설정을 바꾼다. 자기가 기록한 항목만 추가·제거하고 기록 없는 항목은 건드리지 않으며, 크래시 뒤에는 다음 시작의 대조로 정리한다. CI에는 Tailscale이 없어 가짜 CLI로만 증명한다.
- iOS 홈 화면 PWA는 Safari와 저장소가 분리될 수 있어 Safari에서 연결한 자격증명이 홈 화면 앱에 넘어가지 않을 수 있다. 구현은 추가된 페이지 URL로 자격증명을 넘기는 방식을 택하고, 실패하면 홈 화면 앱에서 QR을 다시 찍게 되는지를 설치 후 실제 iPhone 확인에서 본다.
- Web Push는 맥의 인터넷 연결과 Apple·Google 푸시 서비스에 의존하고, iOS는 16.4 이상 홈 화면 설치본에서만 된다. 실패는 로그로만 드러난다.
- Seen 알림 제거는 다음 service worker 실행까지 늦을 수 있다(D-21).
- 폰의 pane 쓰기는 데스크톱 입력과 섞일 수 있다. 데스크톱 포커스는 바꾸지 않으며, 두 입력이 같은 pane에 동시에 오면 도착 순서대로 들어간다.
- 실제 tailnet과 실제 iPhone 확인(QR → 홈 화면 → 앱 닫고 푸시 → 탭 → 답장)은 merge 뒤 운영자 확인이다. 구현 전 사용자에게 필요한 작업은 없다.
- 폰 문구와 설정 문구는 승인된 보드의 것이며 세부 문구는 PR 리뷰에서 거부할 수 있다. D-12, D-13, D-20~D-23은 위임 아래의 에이전트 가정이다.
