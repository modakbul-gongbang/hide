# PRD: 프로젝트별 Overview 제거와 프로젝트 행의 마지막 체크아웃 열기

## Goal

사이드바에서 프로젝트를 눌러 작업으로 돌아가려는 운영자에게, 프로젝트 행이 그 프로젝트에서 마지막으로 포커스한 체크아웃의 Workspace를 열어 준다.
지금은 프로젝트 행과 그 아래 `Overview` 자식 행이 프로젝트 Overview 화면을 열어서, 열려 있는 세션이 있는 프로젝트에서도 작업 대신 조감 화면이 나온다(이슈 #350).
전체 조감은 프로젝트에 속하지 않는 하나의 Overview(이슈 #349)가 맡으므로, 프로젝트마다 따로 가는 Overview 목적지와 그 진입점을 없앤다.
확인할 목표 문장: "프로젝트 행을 누르면 그 프로젝트에서 마지막으로 보던 체크아웃이 열리고, 프로젝트 아래에는 Overview 행이 없으며, 프로젝트 단위 조감은 하나의 Overview 안의 '이 프로젝트' 범위로만 본다."

## Non-goals

- Overview 화면 안의 내용(Agents 그래프, PRs, Issues, Sessions, 디스크)은 바꾸지도 지우지도 않는다. 이 내용은 #349의 Overview가 `이 프로젝트` 범위로 이어받는다. 재검토: #349가 그 범위를 두지 않기로 할 때.
- Overview를 모달/페이지로 여는 방식, 사이드바 맨 위 `Overview` 행, 툴바 아이콘, `⌘⇧O/⌘⇧P/⌘⇧A`, `Home` 행의 Overview 열기는 #349의 몫이다. 이 PRD는 거기에 의존할 뿐 그려 넣지 않는다.
- 체크아웃 행의 클릭 규칙(열기 + 에이전트 펼침, 재클릭으로 접기)과 에이전트 행은 바꾸지 않는다.
- 새 상태를 저장하지 않는다: "마지막으로 포커스한 체크아웃"은 core가 이미 쌓는 최근 체크아웃 목록에서 읽는다(D-02). 프로젝트별 마지막 위치 설정은 만들지 않는다. 재검토: 운영자가 다른 체크아웃을 고정하고 싶다고 할 때.
- Windows/Linux 키 매핑과 Herdr API 계약은 바꾸지 않는다.

## Technical structure

- core: 새 상태·스키마·저장 변경이 없다. 돌아갈 체크아웃은 이미 저장되는 `ui_state.recent_checkouts`를 읽는다. 바뀌는 것은 체크아웃 열기 이벤트의 페이로드에 프로젝트 접기 의도를 실어 보내는 것과 그 admission 검증뿐이다.
- web: `projects.ts`에 돌아갈 체크아웃을 고르는 순수 함수 하나, `sidebar.tsx`에서 `OverviewRow`와 프로젝트 선택 규칙 삭제, `SearchPalette.tsx`·`WorkspaceScreen.tsx`·`keyboard.ts`·`actions.ts`·`recent.ts`에서 프로젝트 주소 Overview 진입점과 이탈 명령 삭제. 화면 종류에서 프로젝트 주소를 가진 `overview`는 #349의 범위 값을 가진 하나의 Overview로 합쳐진다.
- 바뀌지 않음: Herdr 계약, Overview 안의 탭 내용, 체크아웃·에이전트 행, 저장된 접기 상태.

## Risks

- 순서가 어긋나면 조감 화면이 없어진다(D-09). #349 PRD가 `이 프로젝트` 범위를 빼기로 하면 D-05·D-06이 갈 곳을 잃으므로 둘이 같이 확정돼야 한다. 소유: 운영자.
- 열린 결정: D-05(체크아웃 없는 프로젝트가 Overview로 가는 것)와 D-07(프로젝트 이름을 글자로 두는 것)은 가정이며 운영자가 정하지 않았다. 뒤집으려면 이 PRD를 고친다.
- 최근 목록은 10개까지만 담으므로 오래 안 본 프로젝트는 기본 체크아웃으로 열린다. 마지막 위치를 더 오래 기억하려면 별도 저장이 필요하고 이번 범위가 아니다.
- 사용자가 미리 해야 할 일은 없다. 화면 시트 변경은 운영자의 Pen 보드 승인이 구현 전에 필요하다(D-10).
