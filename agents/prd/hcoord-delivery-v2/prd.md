# PRD: hcoord 감시와 전달을 hided로 흡수 (PRD A)

## Goal

hide를 쓰는 운영자와 그 에이전트들은 지금 별도 TypeScript daemon인 hcoord에 의지해 에이전트 사이 request/reply 전달과 부모가 건 감시를 한다.
이 PRD는 그 두 기능을 hided(herdr-core)에 OS 중립 Rust로 새로 만들고 기존 hcoord는 그대로 둔 채 공존시킨다(전체 4단계 중 1단계와 2단계, D-01, D-02, D-41).
이 PRD의 편지 전달은 이 Mac의 로컬 수신자까지이고 원격 기기의 수신자 전달은 PRD B다(D-49).
이 변경 뒤 에이전트는 기존 `hide` CLI의 `request`와 `inbox`로 편지를 보내고 받으며, 편지는 입력창이 비었다고 확신할 때만 울리는 초인종과 `UserPromptSubmit` hook으로 도착하고, 부모가 `hide watch start`로 건 자식은 LLM 없이 20분 무활동일 때 부모에게 알려지고 같은 정지 상태가 이어지면 첫 알림 후 60분에 한 번 더(총 2회) 알려진다.
이유는 hcoord가 따로 배포되고 따로 살며 15분마다 깨우는 소음을 내기 때문이고, 새 엔진을 먼저 만들고 운영 데이터를 본 뒤에야 hcoord를 걷어내는 PRD B를 정하기 위해서다(D-41).

## Non-goals

- PRD B의 범위는 이번에 만들지 않는다: `hide agent spawn --parent here`와 계보 쓰기 이전(3단계), sasu 호출 교체, 열린 hcoord request 이전, mini의 hcoord-test 세션과 e2e 잔재 서버 정리, 재부팅 뒤 감시 공백 판단, hcoord 은퇴(4단계). 결과: sasu가 만든 감시와 spawn은 PRD A 동안 hcoord가 맡고 sasu 런의 15분 watch 소음은 B 뒤에야 사라진다. PRD A를 운영해 본 뒤 별도 인터뷰로 정한다(D-02, D-10, D-11, D-12, D-13, D-15, D-41).
- 원격 기기(mini 등) 수신자에게 편지를 전달하는 것은 이번에 만들지 않는다. 원격 수신자의 `UserPromptSubmit` hook이 이 Mac의 hided 장부에 닿는 경로는 PRD B에서 설계하고, 그동안 원격 수신자에게 가는 편지는 기존 hcoord가 맡으며 1단계 전달 완료 기준은 로컬 수신자로 한정된다. 원격 감시(활동 읽기)는 남고 그 알림은 로컬 부모에게 간다(D-49, D-39).
- 감시 알림은 부모에게만 가고 운영자에게 가는 감시 알림은 PRD B 범위다. 같은 정지 상태의 알림은 2회에서 끝나고 아무 신호가 없어도 깨우는 별도 동작은 없다(D-48).
- 명시적 완료 보고 명령과 그 감시 종료는 만들지 않는다. 일을 끝낸 자식은 20분 뒤 부모가 한 번 알림을 받고 `hide watch stop`으로 끝낸다. sasu의 `implement report`와 함께 PRD B에서 설계한다(D-42).
- 사람 앞 request의 hide Inbox와 ⌘K 표시, 그래프의 막힌 request 표시, 감시 중 에이전트의 아이콘이나 애니메이션은 만들지 않는다. 미전달 알림도 이번에는 장부 상태와 `hide` CLI 조회까지다. 후속 UI PRD에서 Pen 절차로 정한다(D-07, D-14, D-29, design/principles.md rule 13).
- 입력창 초안 복사, 비우기, 복원과 오래된 초안의 자동 정리는 하지 않는다. 초안 때문에 편지가 늦거나 미전달이 되는 대신 의미 있는 초안을 잃지 않는다. 미전달 알림이 실제로 얼마나 오는지 본 뒤 런타임별 키 순서를 검증하고 운영자가 켜는 옵션으로 별도 작업에서 다시 본다(D-08).
- 권한 출처의 세션 단위 증명과 위조 방지는 하지 않는다. 편지에 발신자와 종류를 표시하는 데까지다(D-09, D-22).
- `hide request relay`, `escalate`, `inbox wait`, `graph`, `events`, `status`는 만들지 않는다(D-33). 작업 중 즉시 전달용 PostToolUse 전달은 호출 비용을 재 본 뒤 필요할 때 추가한다(D-05).
- 부모가 없는 에이전트는 감시하지 않는다. 화면 출력 변화 비교와 sasu 형식에 의존하는 신호(PRD 변경 등)는 drift 신호로 쓰지 않는다(D-04, D-26, D-32).
- Herdr를 수정하지 않고, Herdr 고유 기능(pane, PTY, 에이전트 수명, 직접 `agent.prompt`)을 막지 않으며, 입력창 상태 신호의 upstream 제안은 이 PRD의 범위가 아니다(D-30).
- mini에 hided를 상주시키지 않는다. 원격 감시는 이 Mac의 hided가 SSH로 붙는 현재 방식이다(D-13).
- `hide connect`가 세 OS에서 같은 수명 규칙인지에 의존하지 않는다. Windows와 Linux의 e2e와 hook 전달 검증은 #293과 #344가 잇는다(D-28).

## Latest approved contract alignment

PRD B의 Q15("추천대로"), D-26, D-27과 2026-10-04 overnight 승인 범위를 적용한다.
미전달 기한은 10분이고 새 편지는 만들지 않으며 장부와 CLI로 상태를 알린다.
감시는 20분 무활동에서 첫 알림, 첫 알림 후 60분에서 두 번째 알림으로 총 2회이며 재시작 뒤에도 시각과 횟수를 이어간다.
PRD A의 로컬 전달 범위와 hcoord 공존 범위는 유지한다.

## Technical structure

- 장부, 편지 상태 기계, 감시와 틱, 초인종 판정, 단일 내부 전달 함수는 herdr-core(Rust, owner thread의 Runtime)에 새로 들어가고 hided가 기존 hide CLI의 하위명령 `request`, `inbox`, `watch`로 노출한다(D-01, D-03, D-30). Runtime 락 안에서는 메모리 상태만 바꾸고 저장, helper 호출, hcoord 호출은 락 밖이다(D-44, D-39, D-43).
- 장부는 hided가 소유하는 디스크 파일 하나이고(임시 파일 후 rename, 비공개 모드, hide_platform::fs::private) hcoord 장부와 분리된다. 기존 hcoord와의 접점은 감시 등록 때만 락 밖에서 실행하는 `hcoord watch list --json` 한 번과, 활성 감시의 현재 pane/session/machine/hostScope 연결 증명에 필요한 기존 읽기 전용 `hcoord agent list --json` 최대 한 번이다. 전체 기한, 출력 크기와 행 수를 제한하고 프롬프트, 경로, 인수는 기록하지 않으며, 연결 확인 불가는 안정적인 진단 코드 후 등록으로 처리한다(D-43, D-44).
- `hide-agent-hooks`의 `UserPromptSubmit` 처리가 hided에서 대기 편지를 받아 컨텍스트로 출력한 뒤 확정을 호출한다. hided 연결은 hide_platform의 OS별 한 함수를 거친다(D-24, D-35, D-47, D-28).
- 키 입력 경로에 pane별 마지막 입력 시각의 메모리 쓰기가 추가되고, 감시 상태 전이가 스냅샷 wire에 더해진다(D-18, D-38).
- hide-host helper 프로토콜 15에 `session_activity` 호출이 추가되고 hide-session의 SessionLocator와 confirm_label_session을 재사용한다(D-39).
- 편지 전달 대상은 이 Mac의 로컬 pane이다. 원격 수신자 전달 경로는 PRD B이고 원격에 대해서는 session_activity로 활동을 읽는 감시만 있다(D-49).
- Herdr 계약은 바꾸지 않는다. 입력창 상태 API가 없어 화면 읽기를 쓰고 pane 쓰기는 하나의 함수로 모은다(D-17, D-30). 새 외부 서비스, 인증, 결제는 없다.

## Risks

- 초인종 판정은 Herdr 상태(화면 휴리스틱, 1~2초 늦음)와 화면 읽기(TUI 버전 의존, Claude placeholder는 ANSI dim, Codex 슬래시 메뉴 행이 파서를 속일 수 있음)에 기댄다. 불확실하면 보류하므로 안전한 쪽으로 실패하지만 편지가 늦거나 미전달이 될 수 있다(D-19, D-20).
- hide 창 밖 입력(Herdr TUI 직접, 소켓 직접)은 보이지 않아 사람이 막 친 초안에 초인종이 겹칠 수 있고, 휴대폰 답장 경로는 사람 입력과의 겹침 보호가 없다. 알고 받아들인 위험이다(D-18).
- 라이브 증명은 격리 Herdr 서버와 정확히 식별한 후보 PID에서만 하고 운영자의 앱, pane, 서버를 건드리지 않는다(CLAUDE.md의 Performance Guide와 docs/PERFORMANCE_TESTING.md). 격리 e2e와 초인종 실험은 macOS 기준이고 Windows와 Linux의 e2e와 hook 전달은 #293과 #344가 잇는다(D-28). 프로토콜 15의 helper 교체는 무인 운영 중인 mini에서 연결 때 일어나므로 mini에 대한 라이브 확인은 상태를 먼저 읽고 하며 프로세스를 먼저 종료하지 않는다.
- 상한값과 20분, 60분, 30초 기준은 초기값이고 구현 때 측정으로 조정한다. 틱 비용과 입력 지연은 측정 전까지 설명일 뿐이다(D-04, D-46).
- 반대 방향 이중 감시(hcoord가 hide 감시 대상을 등록)는 막지 못하고 운영 규칙으로만 막는다. sasu 런의 15분 watch 소음은 PRD B까지 남는다(D-41, D-43).
- 구현 전에 운영자가 따로 해 줄 일은 없다(자격 증명, 계정, 결제 없음).
- 원칙 intake: engineering/principles.md를 전문 읽었다(oh-my-principle commit 654485f). rule 4, 10은 `ledger_unavailable`, `capacity`, `conflict` 오류와 hook 무음 종료의 진단 로그 행(B6, B10, B17, B40, B45)으로, rule 11은 intent 멱등 행(B13)으로, rule 14, 15는 상한과 틱 소유 행(B18, B32, B33)으로, rule 9는 진단 로그 행으로 옮겼다. design/principles.md는 이번 PRD에 화면 변경이 없어 적용하지 않았고 rule 13만 Non-goals에서 인용한다. 프로젝트 규칙(CLAUDE.md의 락 밖, 상한, 틱 비용)이 우선한다.
- 전달 방식: agents/config.json의 기본(PR 전달, worktree 실행)을 따르며 qa-log에 이를 바꾸는 결정은 없다. 이는 에이전트의 가정이다.
- 열린 항목 (qa-log에 결정이 없어 새로 정하지 않았다. 구현 중 확정하거나 운영자가 정한다):
  - 발신자와 종류를 hided가 무엇에서 알아내는지. 범위는 봉투 자동 부착까지이고 증명은 범위 밖이다(D-09, D-33). capability가 세션 id와 종류를 담지 않는다는 사실(D-22)과의 연결은 구현 중 확정 항목이다.
  - 상태 `만료`가 일어나는 조건과 `미전달`과의 구분. 이 PRD는 `미전달`을 request 기한 10분 안에 전하지 못한 경우(D-07)와 초인종 3회 실패 뒤 기한 경로로 넘어간 경우(D-45)로 읽어 한 경로로 적었다. `만료`는 D-34의 상태 이름이지만 발생 조건이 qa-log에 없어 PRD A는 그 전이를 만들지 않았고, 필요하면 운영자가 조건을 정해 추가한다.
  - 미전달의 "보낸 쪽 알림"이 새 편지로 가는지 장부 상태와 CLI 조회뿐인지. D-07은 장부 상태와 CLI 조회까지라고 하고 D-36은 "알려진다"고 하며, 이 PRD는 전자로 읽었다.
  - request 미전달 기한은 이미 승인된 PRD B Q15, D-26과 overnight 승인 범위에 따라 10분으로 고정한다. 장부 파일 위치와 hook의 수신자 식별 방법은 구현 중 확정 항목이다.
  - 재시작 뒤 알림 횟수와 두 번째 알림 시점은 이미 승인된 PRD B Q15, D-27로 확정되었다. 첫 알림 시각과 횟수를 저장하고 첫 알림 후 60분의 두 번째 알림을 이어가며 활동 재개 때 초기화한다.
  - D-48의 "첫 알림 후 60분"은 이미 승인된 PRD B Q15, D-27에 따라 첫 알림 시각부터 60분이다. 전달 기한 10분과 별개의 감시 규칙이다.
  - 반대 방향 hcoord 등록으로 생기는 이중 감시와 부모의 중복 알림은 D-43이 받아들인 잔여 위험이며 완료 기준 7과 8은 hide 쪽 충돌 검사 범위로 읽는다.
  - `hide watch list`는 Q3와 Q9의 문구에서 가져왔고 Decision Register 행은 없다. D-32의 `hide agent spawn --parent here`는 3단계 소관이어서 이 PRD에서 제외했다.
  - qa-log의 D-38은 8번을 "이중 감시 없음"으로 적고 있어 이 PRD의 한정(hide 쪽 충돌 검사 범위)과 문구가 다르다. 번호 40번은 qa-log에 비어 있다.
