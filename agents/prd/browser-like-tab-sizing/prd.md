# PRD: 브라우저형 탭 폭 축소

## Goal

Hide 사용자가 탭 수와 창 폭에 관계없이 가로 스크롤 없이 현재 탭을 찾고 전환할 수 있도록, 탭 스트립을 브라우저처럼 기본 폭에서 균등 축소하고 공간이 부족하면 아이콘형과 명시적인 오버플로 상태로 전환한다.

## Non-goals

- Herdr가 소유하는 탭 존재, 정규 순서, 활성 탭, MRU, 세션 상태의 권한이나 저장 형식은 바꾸지 않는다.
- 탭 개수에 새 상한을 두지 않는다. 아이콘형 최소 폭의 수용량을 넘기면 탭 생성을 막는 대신 오버플로 메뉴로 접근성을 보존한다.
- 오버플로 메뉴 안에서 직접 드래그 재정렬하는 새 조작은 만들지 않는다. 사용자는 숨은 탭을 먼저 선택해 스트립에 표시한 뒤 기존 드래그를 사용하며, 직접 조작 요구가 확인될 때 재검토한다.
- 코어 C ABI, Herdr Socket API, 플러그인, 터미널 렌더링, 편집기 본문, 사이드바 및 상태 바의 동작은 변경하지 않는다.
- 이 작업에서 설치된 운영 앱이나 운영 Herdr 서버를 교체하거나 조작하지 않는다. 검증은 격리 개발 번들과 전용 서버 또는 기록 스냅샷에서만 수행한다.

## Technical structure

셸의 표시 계층에 가용 폭, 정규 탭 목록, 활성 탭 식별자를 입력으로 받아 각 슬롯 폭과 시작점, 밀도, 보이는 연속 구간, 숨은 탭 목록을 내는 순수하고 결정적인 적응형 탭 표현을 둔다.
렌더링과 드래그 목적지 계산은 그 한 결과를 공유하고, 기존 실제 폭 Preference와 수평 ScrollView를 제거한다.
탭의 정규 순서와 활성화 권한은 계속 코어에 있으며 셸은 기존 typed event만 보낸다.
새 저장 상태, 마이그레이션, 서비스, 의존성, API, 권한 또는 외부 데이터 흐름은 추가하지 않는다.
폭과 밀도 값은 `HideTheme`와 디자인 토큰 계약에서 관리하고 `DESIGN.md` 및 단일 디자인 캔버스가 같은 상태 전이를 문서화한다.
탭 스트립의 바깥 시작 inset과 각 탭 내부 identity 여백은 별도 레이아웃 책임으로 유지해, 바깥 8pt 제거가 아이콘 hit target이나 traffic light 보호 공간을 축소하지 않게 한다.
구현은 루트 `main` checkout을 그대로 둔 격리 worktree에서 수행하며, 결과는 `main` 대상 pull request로 전달하고 명시적인 사용자 승인 전에는 병합하지 않는다.

## Risks

- 매우 좁은 창에서 활성 탭 중심 구간이 잦게 바뀌면 위치 감각을 잃을 수 있다. 정규 순서를 유지하고 메뉴를 전체 숨은 탭의 안정적인 탐색면으로 사용해 범위를 제한한다.
- 40pt compact 상태에서 notice·dirty·preview가 한 슬롯에 경쟁할 수 있다. 아이콘과 상태 mark를 왼쪽 identity 영역에 함께 유지하고 전체 툴팁·접근성 설명을 실제 개발 번들에서 확인한다.
- 탭 스트립 바깥 inset과 탭 내부 여백을 함께 제거하면 첫 아이콘이 창 경계에 달라붙거나 sidebar-hidden 상태에서 traffic light와 겹칠 수 있다. sidebar-visible의 8pt만 제거하고 compact identity 및 69pt traffic-light inset을 각각 회귀 테스트한다.
- 렌더링 폭과 드래그 폭이 갈라지면 잘못된 위치로 재정렬될 수 있다. 두 경로가 동일한 결정적 레이아웃 결과를 사용하고 외부 관찰 기준의 단위 테스트로 경계를 고정한다.
- SwiftUI의 창 크기 측정이 초기 프레임에서 불안정하면 탭이 순간적으로 흔들릴 수 있다. 유효한 가용 폭만 적용하고 확대·축소 왕복을 실제 창에서 확인한다.
- 디자인 파일의 생성 영역이나 변수 규칙을 어기면 캔버스가 조용히 드리프트할 수 있다. 생성기와 디자인 계약 검사를 거치며 별도 `.pen` 파일이나 literal 토큰을 만들지 않는다.
- 네이티브 증거는 정확히 식별한 격리 개발 번들 PID와 창을 대상으로 수집한다. 이미 실행 중인 운영 Hide 앱과 운영 Herdr 서버는 종료, 포커스, 재시작, 설치 변경의 대상이 아니다.
- 구현 전 사용자에게 필요한 추가 자격 증명, 구매, 계정 설정 또는 운영 작업은 없다.
