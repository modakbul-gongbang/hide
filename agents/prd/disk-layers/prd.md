# PRD: Overview 레이어별 디스크 정리

## Goal

운영자는 워크트리마다 쌓인 빌드 산출물로 디스크가 바닥나는 일을 겪는다(2026-09-29 볼륨 여유 1.6 GiB, herdr-ide의 빌드 캐시만 약 38 GB).
지금 Overview는 디스크 합계 숫자 하나만 보이고, 무엇이 공간을 쓰는지, 무엇을 지워도 되는지는 운영자가 터미널에서 찾아 지워야 한다.
이 PRD는 Project Overview에서 체크아웃 x 레이어 표를 열어 빌드 도구가 다시 만드는 것(빌드 캐시, 의존성)과 머지가 증명된 워크트리를 골라 한 번에 비우게 한다.
운영자가 확인할 한 문장: "Overview 디스크 숫자를 누르면 체크아웃마다 빌드 캐시 · 의존성 · 워크트리 크기가 보이고, 끝난 것을 골라 한 번에 비우며, 결과는 늘어난 볼륨 여유로 확인한다."
근거 보드: `agents/runs/disk-layers/design/disk-layers-v6.pen` (입구, A-1, A-2, 체크박스 범위, 결과, 분류 규칙).

## Non-goals

- 원격 기기 프로젝트는 측정하지도 정리하지도 않는다 (D-19). 결과: 원격 프로젝트 Overview에는 지금처럼 디스크 숫자와 시트가 없다. 되돌릴 조건: 원격 기기의 디스크가 실제로 문제될 때.
- 기타(어느 규칙에도 없는 무시된 폴더, `agents/runs` 포함)는 크기만 보이고 지우지 않는다 (D-10). 결과: 도구 고유 폴더는 그 도구로 정리한다.
- 프로젝트가 레이어를 선언하는 파일(`.hide/disk.toml`)은 없다 (D-11). 되돌릴 조건: 기타가 커서 운영자가 선언을 원할 때.
- 휴지통과 되돌리기는 없다 (D-16). 결과: 지운 캐시는 다음 빌드나 install이 다시 만든다.
- 이 시트는 브랜치를 지우지 않고, 머지되지 않은 워크트리(closed PR 포함)를 지우지 않는다 (D-17). 결과: 그런 삭제는 기존 Delete worktree 대화상자로 한다.
- 모든 프로젝트 Overview, 오른쪽 패널 Overview, 자동 · 주기 정리, 프로젝트 밖 캐시(`~/.cargo`, pnpm store, DerivedData)는 범위 밖이다. 되돌릴 조건: 프로젝트 단위 정리로 여유가 모자랄 때.
- 디자인 원칙 1 · 6 · 13, 엔지니어링 원칙 4 · 15 (`oh-my-principle`, D-32): 표로 비교하고, 되돌릴 수 없는 워크트리 삭제만 확인하며, 운영자가 손쓸 수 없는 실패는 로그로 보낸다. 관찰 가능한 형태는 B6, B18, B22에 있다.

| B4 | 시트의 표는 행마다 브랜치 이름과 PR 칩, 빌드 캐시 · 의존성 · 워크트리 · 기타 · 합계 칸을 보이고, 열 머리는 이름과 보이는 행의 열 합계만 보이고 부제 · 열 머리 둘째 줄 · 막대 아래 범례는 없다(막대 조각은 멈추면 레이어 이름과 크기를 말한다). main이 맨 위, 나머지는 합계 큰 순이며 1 GB 미만 체크아웃은 `작은 체크아웃 N · X GB` 한 줄로 접혀 누르면 펼쳐진다. | D-08, D-21 |

## Technical structure

- 코어 측정: `disk.rs`의 walk가 체크아웃마다 무시된 폴더를 레이어로 분류해 칸별 합계를 모은다. gitignore는 hide-host의 `ignore` 사용을 재사용하고, CACHEDIR.TAG 서명 확인과 생태계 규칙표는 코어 모듈 하나가 소유한다. 체크아웃마다 상한을 따로 두고, 같은 reader가 프로젝트 볼륨의 여유를 `statvfs`(이미 의존성인 `libc`)로 읽는다. 폴더 경로 목록은 코어에만 두고 wire에는 칸 합계 · 폴더 수 · 가장 큰 폴더 이름과 볼륨 여유만 싣는다.
- 코어 이벤트: 웹 호출부가 없던 `cleanup_review`는 프로젝트 `workspace_id`를 받아 워크트리 적격성(기존 규칙 + 무시된 폴더 안 저장소 검사), 캐시 칸, 쓰는 중을 한 검토로 만든다. `cleanup_confirm`은 검토 id, 워크트리 경로, 캐시 칸(체크아웃, 레이어)을 한 번에 받는다. `CleanupSnapshot`이 이 검토 · 진행 · 결과를 싣고 웹이 처음으로 읽는다. 새 병렬 이벤트는 없다.
- 쓰는 중: 체크아웃별 에이전트 요약, 해당 체크아웃 pane들의 Herdr `pane.process_info`(검토와 확인 때만, 락 밖, 체크아웃 pane 수로 제한), 기존 `ports.rs` 리스너 cwd로 판정한다.
- 실행: 기존 `hide-worktree-cleanup` 워커가 체크아웃마다 추적 파일 확인(git 한 번, 락 밖)과 재검사를 한 뒤 폴더를 git 공통 디렉터리의 `hide-removed`로 옮기고, 기존 청소 스레드가 지운다. 워크트리는 기존 non-force 경로 그대로이며 `check-worktree-removal-boundary.sh`는 바뀌지 않는다. 청소가 끝나면 볼륨 여유를 다시 읽고 디스크를 다시 잰다.
- 셸: 시트는 `WorkspaceDialogs`의 새 kind이고, 선택 · 필터 · 접힘 · 바닥 줄 계산은 순수 함수로 두어 단위 테스트가 D-09 · D-22 규칙을 단언한다. `contracts/hided-ws.schema.json`이 넓어진 스냅샷과 이벤트를 따른다.
- 디자인: `System / Checkbox`에 Indeterminate(갤러리 manifest, Pen, 코드), 시트는 `scripts/pen-screens.mjs`로 `design/hide-screens.pen`에 그린다. System / Table은 만들지 않는다.
- `AGENTS.md` 규칙(락 아래 subprocess · 블로킹 I/O 없음, 사용자 행동은 이벤트 하나, 틱마다 git fork 없음)을 지킨다. 측정 비용이 바뀌므로 `docs/PERFORMANCE_TESTING.md`의 디스크 계약도 같이 고친다.

## Risks

- 삭제는 되돌릴 수 없다. 범위는 무시된 폴더 중 CACHEDIR.TAG나 표식 파일이 증명한 것, 추적 파일 · 다른 저장소 · 심링크 제외, 확인 때 재검사로 묶는다. 자동 테스트와 실측은 사설 fixture root에서만 하고 운영자 프로젝트를 정리 대상으로 쓰지 않는다(CONTRIBUTING.md:108).
- 규칙표 오분류: 무시된 `build/`에 손으로 만든 자료를 두는 저장소가 있을 수 있다. 표식 파일과 무시 두 조건을 모두 요구하고, 나머지는 기타로 떨어진다.
- 할당과 실제 회수량은 다르다(pnpm의 APFS 클론, 다른 곳의 hard link). 결과는 볼륨 여유 전후만 말하므로 실제로 늘어난 양이 곧 결과다.
- 측정 비용: 열 때마다 walk에 gitignore 판정이 더해진다. 체크아웃별 상한과 락 밖 실행으로 묶고, 측정 결과를 PR의 Evidence에 idle · driven으로 나눠 적는다.
- 쓰는 중 판정은 Herdr 밖(다른 앱의 IDE 빌드)에서 도는 프로세스를 모른다. 그 경우 지운 캐시는 다음 빌드가 다시 만든다.
- 커밋 없는 새 워크트리는 기존 done 판정과 코어 머지 증명 모두에서 머지됨으로 읽힌다. 캐시 정리에는 해가 작고, 워크트리 삭제는 clean과 pane 없음을 함께 요구한다.
- D-21 ~ D-31은 되돌릴 수 있는 가정이며 운영자가 검토에서 뒤집을 수 있다. 운영자가 미리 준비할 것은 없다.
