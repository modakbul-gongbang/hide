# PRD: Agent 탭 단계적 축소

## Goal

좁은 Agent 영역에서 여러 에이전트를 쓰는 운영자가, 탭이 늘어나도 바를 끝까지 쓰면서 제목을 최대한 오래 보도록 Agent 탭 스트립의 축소를 전부-아니면-전무에서 단계적 축소로 바꾼다.
지금은 탭 6개, 탭 공간 약 485px에서 모든 탭이 40px 마크로 접혀 바의 절반 가까이가 비는데, 바뀐 뒤에는 선택된 탭이 제목을 유지하고 나머지 탭이 남은 공간을 나눠 가지며 마크는 더 줄일 수 없을 때만 나타난다.

## Non-goals

- File View 탭 스트립은 바꾸지 않는다. View 탭은 지금처럼 제목을 유지하고 104px에서 스크롤한다. 파일 탭의 마크 설계와 탭이 놓일 컬럼이 #321에서 정해진 뒤 같은 스트립 인터페이스를 다시 검토한다.
- `design/hide-ui.lib.pen`의 `Component / Adaptive Work Tab`은 이 변경에서 편집하지 않는다. 새로 생긴 축소 상태(제목 일부와 마크, 닫기 컨트롤 없음)는 PR에 디자인 후속으로 보고하고, 디자인 라이브러리 작업에서 반영한다.
- 탭 순서, 선택, 닫기, 이름 바꾸기, 드래그의 의미와 코어·Herdr 쪽 상태는 바꾸지 않는다.
- 탭 수 상한이나 오버플로 메뉴를 새로 만들지 않는다. 마크로도 넘치면 지금처럼 스트립이 스크롤하고 선택된 탭이 보이는 자리에 남는다.

## Technical structure

셸 표시 계층만 바뀐다.
`areaLayout.ts`에 탭 공간, 탭 수, 기존 크기 토큰을 받아 선택된 탭과 비선택 탭 각각의 폭과 표시 상태를 내는 순수 함수가 `iconTabs`를 대체한다.
`AreaTree.tsx`의 Agent 탭 바는 지금처럼 탭 바깥 영역을 측정하고, 그 결과를 슬롯 폭과 탭의 표시 상태로 적용한다; 탭 상호작용 타입은 불리언 대신 표시 상태를 넘긴다.
코어, 와이어, Rust 크레이트, 디자인 토큰, `.pen` 파일, 저장 상태, 외부 서비스는 바뀌지 않는다.

## Risks

- 창을 끄는 동안 탭 바가 폭 변화마다 다시 그려진다. 바 하나와 메모된 탭 버튼으로 범위가 묶이고, 영역 분할선 드래그는 놓을 때 한 번만 반영되므로 높은 빈도 경로가 아니다.
- 디자인 라이브러리의 `Component / Adaptive Work Tab`은 새 축소 상태를 그리지 않는다. HANDOFF에 따라 `.pen`은 편집하지 않고 PR에서 후속으로 보고한다.
- 인터페이스 글자 크기를 키우면 같은 폭에 보이는 제목 글자 수가 줄어든다. 폭은 토큰 px로 고정이며 제목은 잘리고 툴팁이 전체를 말한다.
- 이 Mac mini는 화면이 잠겨 있었던 적이 있어 네이티브 앱 화면 확인이 불가능할 수 있다. 그 경우 격리된 hided와 Herdr에 붙인 Playwright e2e의 측정과 스크린샷을 근거로 삼고, 네이티브 확인은 하지 않았다고 명시한다. 설치된 `/Applications/hide.app`와 운영 Herdr 서버는 건드리지 않는다.
- 구현 전에 사용자가 해야 할 일은 없다.
