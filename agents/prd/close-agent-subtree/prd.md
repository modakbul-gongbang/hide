# PRD: Close a parent agent together with its descendants

## Goal

hide 운영자는 에이전트가 hcoord로 하위 에이전트를 위임해 두고 일을 끝낸 뒤 그 에이전트를 닫는다.
지금은 위임된 자식이 자기 탭에 있어서 부모만 닫히고, 부모를 잃은 자식은 아무 확인 없이 운영자 소유 root로 올라와 그 질문과 완료가 Needs You와 Done에 뜨기 시작한다.
목표: 하위 에이전트가 있는 에이전트의 pane이나 탭을 닫거나 그 checkout을 Delete worktree나 Remove project로 지울 때, 운영자가 한 확인창에서 진행 중이거나 확인 안 된 하위를 한눈에 보고 부모(또는 삭제 대상)만 처리할지 하위 트리 전체(원격, 잠든 하위 포함)를 함께 닫을지 고르게 하며, 하위까지 닫는 동작은 도중에 자식이 운영자 목록으로 튀지 않게 한 작업으로 실행한다.

## Non-goals

- 삭제 확인창의 동작 버튼에는 초기 포커스를 두지 않는다(D-35). 폴더 삭제는 되돌릴 수 없어서다. 운영자가 삭제에도 Enter 기본값을 원하면 다시 본다.
- Reopen closed tab으로 되살린 에이전트 사이의 계보는 복구하지 않는다(D-24). 다시 연 부모와 남은 자식은 따로 root로 보인다. hcoord가 되살린 pane에 parent_pane을 다시 쓸 수 있게 되면 다시 본다.
- 원격 닫기에 reopen 항목을 새로 만들지 않는다(D-24). 원격 기기 reopen이 따로 생기면 다시 본다.
- 연결이 끊긴 기기의 하위는 나열하지도 닫지도 않는다(D-16). 그 에이전트는 기기가 다시 연결되면 root로 보인다.
- "다시 묻지 않기"나 선택 기억 설정은 만들지 않는다. 매번 묻는 비용이 불만으로 돌아오면 다시 본다.
- Pen 라이브러리와 화면 시트는 바꾸지 않는다(D-28). 기존 셸의 클라이언트 쪽 하위 트리 계산 네 곳은 리팩터링하지 않는다.
- 하위 배지 목록에는 여전히 Stop 동작을 넣지 않는다(docs/UI_BEHAVIOR.md:257).

## Technical structure

- 코어(herdr-core): 전역 계보 패스(refresh_agent_lineage에서 부르는 apply_lineage)가 에이전트 행마다 살아 있는 하위 pane id 목록을 닫는 순서로 계산해 additive 필드로 publish한다. stale 기기의 행은 제외하고, 하위가 없는 행에서는 필드를 생략한다.
- 코어: 새 이벤트 하나(대상 pane 또는 탭, 보여준 pane id 목록, confirmed)가 트리 닫기 작업 하나를 만든다. 이 작업은 기존 로컬 pane/탭 닫기와 원격 close를 깊은 순서로 이어 붙이고, 들어올 때 수용 여부와 pane별 규칙을 한 번에 확인한다. 진행 상태는 기존 async operation 표시로 내보낸다. Herdr 호출은 지금처럼 pane.close와 tab.close뿐이다.
- 코어: Delete worktree와 Remove project는 운영자가 하위까지 닫기를 고르면 같은 트리 닫기 작업을 먼저 실행하고, 그 작업이 모두 끝났을 때만 기존 삭제 작업을 시작한다. 이것만 삭제는 기존 삭제 이벤트 그대로다.
- 런타임 경계: Mutex&lt;Runtime&gt; 아래에서 subprocess나 blocking I/O를 하지 않는다. 순서 진행은 기존 비동기 effect와 topology 확인으로 한다.
- hided: 새 이벤트를 지금처럼 그대로 통과시킨다. contracts/hided-ws.schema.json과 생성된 web 타입이 이벤트를 기술하면 함께 고친다.
- 웹: web/src/close.ts의 판단이 코어의 하위 목록을 읽어 시트 내용을 정하고, ui.ts의 대기 상태가 행을 담으며, Overlays의 시트가 세 버튼으로 그린다. 요약 줄과 하위 목록은 닫기 시트와 삭제 확인창(WorkspaceDialogs)이 같은 부품으로 쓴다. AlertDialog에는 Action 초기 포커스 옵션을 더한다.
- 문서: docs/UI_BEHAVIOR.md(닫기, 897 예외, pane 메뉴, 에이전트 행 메뉴, Delete worktree 확인창, Removing a project's registration), docs/status-model.md(닫기 보호와 하위 트리), 닫기 모델이 바뀌면 docs/ARCHITECTURE.md를 같은 변경에서 고친다.
- 저장 데이터, 마이그레이션, 인증, 외부 서비스 경계는 바뀌지 않는다.

## Risks

- 잘못된 하위 계산이나 순서는 관계없는 에이전트 작업을 멈춘다. 보여준 id만 닫고, 코어가 도착 시 다시 확인하며, 코어 테스트가 순서와 제외 규칙을 막는다.
- Enter 기본값(D-18)은 운영자의 명시적 선택이지만 문서 계약과 디자인 원칙 #6에 대한 예외다. 되돌리기 쉬운 결정이므로 PR 리뷰에서 운영자가 다시 판단할 지점이다.
- 깊은 트리는 단계마다 topology 확인을 기다려 한 번에 닫는 것보다 느리다. 단계마다 기존 5초 시한이 있고, 시한을 넘기면 B14의 실패로 끝난다.
- 원격 닫기에는 사전 재확인과 reopen이 없어서, 원격 하위의 닫기는 되살릴 수 없다(운영자가 알고 승인, D-09).
- 하위까지 닫고 삭제는 하위 닫기가 끝나야 삭제가 시작되므로 삭제가 늦어질 수 있다. 하위 실패는 삭제를 막고 확인창이나 배너로 보인다(B22).
- 실제 검증은 격리된 Herdr 서버와 후보 앱 창에서만 한다. 운영자의 /Applications/hide.app, pane, 서버는 건드리지 않는다.
- 구현 전에 운영자가 해야 할 일은 없다.
